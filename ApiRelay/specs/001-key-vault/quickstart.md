# 验收指南（Quickstart）

**Feature**: 密钥保管、分发与用量统计（阶段一）
**Date**: 2026-08-04
**依据**: [spec.md](./spec.md) · [plan.md](./plan.md) · Constitution v2.0.0

> 本文是**人工验收清单**，按用户故事优先级排列。每条给出前置条件、操作、期望结果与对应需求编号。

## 1. US1 — 保管与取出密钥（P1）

### 1.1 录入与列表

1. 新建上游账号「我的 OpenRouter」，平台选 OpenRouter。
2. 在其下录入一把密钥，命名「VS Code」。
3. **期望**：列表按平台分组显示该密钥，**不展示密钥的任何字符**，任何位置都不出现完整明文。（FR-001、FR-002）

### 1.1a 录入正确性（FR-056、FR-057 / SC-012）

1. 系统设置中开启智能标点与自动大写；在密钥输入框粘贴含 `-` 的密钥字符串。
2. **期望**：字符不被替换为 `–` 等智能标点，大小写不被自动改动；控件已关闭自动更正/大写/智能标点。
3. 粘贴带首尾空白或中间换行的内容 → **期望**去空白后可存，或明确拒绝并说明原因；**不得**静默存入破坏后的明文。
4. 在同一上游账号下再录入一把**明文完全相同**的密钥 → **期望**提示可能重复并指出已有那一条；确认后才保存。**不得**为此写入明文哈希或末位片段。

### 1.1b 新增并指定使用方步数（FR-025 / SC-001）

前置：干净安装或空库；已有至少 1 个使用方工具（预置或自建）。

1. 从主界面开始，完成「保存一把新密钥并指定使用方」（可在保存后立即指派）。
2. 只计**关键确认**步（点「完成/保存/指派确认」等）；**不计**系统权限弹窗与身份确认 sheet。
3. **期望**：全程 ≤ **3** 步；无阻塞性错误。验收口径：自测 5 次均满足（SC-001）。
4. **不合格**：必须先离开主流程进入深层设置页才能指派，或确认步数 ≥4。

### 1.2 门闩：默认档（不验证）

1. 设置 → 取出密钥明文的验证方式 = **不验证**（默认）。
2. **期望**：设置界面**只有一个开关**管辖「查看」与「复制」，**不存在**两个独立开关。（FR-003、宪法 VIII）
3. 点「查看明文」→ 直接显示，无验证。点「复制」→ 直接复制，无验证。
4. **反向验收**：任何实现若允许「复制不验证但查看要验证」，即为**不合格**——用户可用复制绕过查看门闩。

### 1.3 门闩：生物识别或设备密码档

1. 设置中把验证方式改为 **生物识别或设备密码**。
2. 点「查看明文」→ **期望**弹出 Face ID；通过后显示明文；取消则不显示。（FR-003）
3. 点「复制」→ **期望**同样弹出验证。

### 1.4 门闩：仅生物识别档

1. 在**无生物识别能力**的设备上打开设置。
2. **期望**：`仅生物识别` 档**不可选**，且给出原因说明。（FR-003）
3. 在有 Face ID 的 iPhone 上，文案显示「Face ID」；在有 Touch ID 的 Mac 上显示「触控 ID」。
   **期望**：**不存在**把「面容识别」与「指纹识别」并列为两个可选项的界面。（FR-003a）

### 1.5 ⚠️ 剪贴板限时清除（真机）

1. 设置剪贴板清除时长 = 2 分钟（默认）。复制一把密钥。
2. 立即在「备忘录」粘贴 → **期望**得到明文。
3. 等待 2 分钟后再次粘贴 → **期望**取不到该明文。（FR-005）
4. **⚠️ 关键**：复制后**强制杀掉 App**，再等满 2 分钟后粘贴 → **期望仍被清除**
   （证明用的是系统 `.expirationDate` 而非应用内计时器）。
5. **连续复制**：复制密钥 A，30 秒后复制一段普通文本，等到 A 的 2 分钟到点 →
   **期望**普通文本**未被误清**。（FR-005）

### 1.6 ⚠️ 通用剪贴板开关（真机，需两台设备）

1. 开启「禁用通用剪贴板」，在 iPhone 复制密钥。
2. 到 Mac 上粘贴 → **期望**取不到该内容。
3. 关闭该开关重复一次 → **期望**可取到（证明开关真实生效）。（FR-004）

### 1.7 ⚠️ iCloud 钥匙串同步（真机，需两台设备）

1. iPhone 上录入一把新密钥。
2. 两台设备均登录同一 Apple ID 且开启 iCloud 钥匙串，等待同步。
3. Mac 上打开应用 → **期望**该密钥出现且**可取出明文**。（FR-033）
4. **未同步态验收**：在 Mac 上人为造出「元信息已到、明文未到」的状态 →
   **期望**显示明确的「本机暂无明文」状态与等待提示，**而非**报错崩溃或显示空字符串。（data-model §9）

### 1.8 免费额度

1. 保持免费权益，录入到第 3 把密钥。
2. 尝试录入第 4 把 → **期望**被拦截，并说明「免费版最多 3 把」及解锁方式。（FR-026）
3. 删除 1 把（进回收站）后再录入 → **期望**成功（回收站不计额度）。

### 1.9 最近删除回收站（FR-006 / DC-029）

1. 删除一把已指派的密钥 → **期望**主列表消失，出现在「最近删除」，显示剩余天数。
2. 经身份确认后恢复 → **期望**回到主列表，指派关系仍在，可复制明文。
3. 再删一次，在回收站选「立即删除」→ **期望**不可再恢复；Keychain 无该条目。
4. （可选）将某条 `purgeAfter` 拨到过去并冷启动 → **期望**启动巡检后被永久清除。
5. 回收站内勾选多条（或全选当前可见结果）后批量恢复 / 立即删除 → **期望**只确认一次身份；免费额度不够则一条都不恢复；立即删除会先问数量（FR-006a）。

## 2. US2 — 指派使用方与双视角（P1）

1. 新建使用方工具「VS Code」「OpenCode」。把两把不同上游平台的密钥分别指派给二者。
2. 切换到「按平台」视角 → **期望**按上游账号分组。
3. 切换到「按使用方」视角 → **期望**按工具分组，可跨平台。（FR-008）
4. 留一把不指派 → **期望**在使用方视角下归入「未分配」，**不消失**。
5. 删除使用方「VS Code」→ **期望**其下密钥**不被删除**，而是回到「未分配」。（data-model §9）

### 2.1 多对多指派（关键）

1. 把**同一把密钥**同时指派给「VS Code」和「OpenCode」。
2. **期望**：指派成功，界面明确标记该密钥「被 2 个工具共用」。（FR-007）
3. 取消它对「VS Code」的指派 → **期望**它对「OpenCode」的指派**不受影响**，仍为已分配。
4. **⚠️ 计数自洽验收**：在「按使用方」视角下，各分组去重后的密钥总数**必须等于**
   「按平台」视角的总数。共享密钥被计两次即为**不合格**。（SC-005、FR-008a）

### 2.2 共享密钥的用量归属（V2 验收项，V1 跳过）

1. 让一把共享密钥产生用量。
2. **期望**：其用量归入独立的「共享密钥」小计项，**不摊分到 VS Code 与 OpenCode**，
   也**不重复计入二者**，并给出说明（上游平台无法拆分同一把密钥在不同工具间的消耗）。
3. **反向验收**：若界面把共享密钥的用量平均摊给两个工具，或两个工具各显示全额，
   即为**不合格**——那是编造数据。（FR-008a、宪法 IX）
4. **自洽等式**：`独占密钥之和 + 共享密钥小计 + 未分配小计 == 按平台维度总量`。

### 2.3 两类平台都可自定义添加

1. 添加一个未预置的**上游平台**（如某个自建 OpenAI 兼容服务），填写名称与自定义接入地址。
   → **期望**添加成功，可在其下录入密钥。（FR-007a）
2. 添加一个未预置的**使用方工具**（如「Zed」）→ **期望**添加成功，可被指派。
3. 尝试删除一个**预置项** → **期望**只能隐藏，不能物理删除（应用更新会重新引入）。
4. **术语检查**：界面上 MUST 能清楚分辨「上游平台」与「使用方工具」两个概念，
   MUST NOT 用同一个「平台」措辞混指二者。（spec.md 术语表）

## 3. US3 — 在 App 内签发与作废（P2）

### 3.1 OpenRouter（支持）

1. 为该账号配置 Management Key → **期望**配置时弹出验证，且**该验证无法在设置中关闭**。（宪法 VIII）
2. 在 App 内创建一把密钥，设置消费上限。
3. **期望**：创建成功，明文自动入库，无需用户手动复制粘贴。（FR-009）
4. 在 App 内禁用该密钥 → **期望**平台后台可见其已禁用状态。

### 3.2 OpenAI / Anthropic / DeepSeek（不支持）

1. 打开这些平台账号的密钥创建界面。
2. **期望**：「在 App 内创建」入口**提前置灰或不显示**，并给出前往官网的说明，
   **而不是**点了才报错。（FR-011）

### 3.3 两步一致性（需人为注入故障）

1. 模拟「平台侧创建成功但本地 Keychain 写入失败」。
2. **期望**：出现**不可忽略**的提示，说明平台侧已产生一把无法取回明文的密钥，
   并指引用户前往官网处理；**期望系统未自动删除平台侧密钥**。（FR-010）

## 4. US4 — 用量与余额（P2）

### 4.1 各平台能力的诚实呈现 —— 本期最容易做错的一项

| 平台 | 期望呈现 |
|------|----------|
| OpenRouter | 显示平台给出的**费用金额**；token 数显示「平台未提供」，**不显示 0** |
| OpenAI | 显示 **token 数**；费用标注为「本产品估算」并可见所用单价 |
| Anthropic | 同上；缓存 token **只显示数量**并标注「未计入估算」 |
| DeepSeek | 按密钥用量位显示「该平台不支持按密钥统计」；账户余额正常显示 |

**反向验收**：任何平台的未知数值若被显示为 `0`、`-`、或留空而无说明，即为**不合格**（宪法 IX）。

### 4.2 平台数字与本产品估算必须可区分

1. 查看任一 OpenAI 密钥的费用。
2. **期望**：界面明确区分「平台给出」与「本产品估算」，用户能看出这是估算而非账单。（FR-015）

### 4.3 自动刷新不打断用户

1. 设置刷新间隔 = 15 分钟。把应用留在前台。
2. **期望**：到点自动刷新，**全程不弹出任何身份验证**。（FR-021a、宪法 VIII）
3. **反向验收**：若自动刷新弹出 Face ID，即为**不合格**。

### 4.4 故障隔离

1. 故意把 OpenAI 的 Admin Key 改错，触发全量刷新。
2. **期望**：OpenAI 显示可读的失败原因与上次成功时间；**其他平台正常刷新**；
   密钥保管与复制功能完全不受影响。（FR-018、宪法 V）
3. 断网后刷新 → **期望**保留上次数据 + 显示时间戳，**不清空**。（FR-017）

### 4.5 单价变更不改写历史

1. 记录某条用量的估算费用。修改对应单价规则。
2. **期望**：**历史快照的估算值不变**；仅新拉取的数据用新单价。（FR-019、宪法 IX）

### 4.6 ⚠️ 后台刷新（真机，需耐心）

1. 设置间隔 15 分钟，把应用切到后台，正常使用设备数小时。
2. **期望**：可能刷新、也可能不刷新——这是系统行为，**不作为不合格判据**。
3. **真正的验收点**：设置项说明**必须**告知「后台刷新由系统调度，不保证按设定间隔执行」。
   若文案承诺「每 15 分钟刷新」，即为**不合格**。（FR-021a、FR-023）

## 5. US5 — 付费解锁（P3）

1. 用 StoreKit Configuration 文件在沙盒中完成一次买断购买。
2. **期望**：额度上限解除，可录入第 4 把及以上。（FR-027）
3. 点「恢复购买」→ **期望**功能存在且可用（**苹果审核必查项**，缺失会被拒）。（FR-028）
4. **降级验收**：撤销购买后 → **期望**超出 3 把的密钥**只读保留，可看可删，不被清空**，
   且不允许新增。（FR-029）
5. **期望**：付费界面**不出现**任何「中转」相关权益（本期不可达）。（FR-032）

## 6. US6 — 设置（P3）

逐项验证「变更立即生效」且「重启后保持」：

| 设置项 | 验收要点 |
|--------|----------|
| 打开 App 需要身份确认 | 冷启动触发验证；自动锁定时长到点后再次触发 |
| 取出密钥明文的验证方式 | **四档**（不验证（默认） / 生物识别或设备密码 / 仅生物识别 / 应用主密码）；查看与复制共用；见 §1.2–1.4 |
| 剪贴板清除时长 | 含 2 分钟档；见 §1.5 |
| 禁用通用剪贴板 | 见 §1.6 |
| 在应用切换器中隐藏 | 多任务界面显示遮罩，不泄露密钥列表 |
| 外观 | 浅色 / 深色 / 跟随系统即时生效；**仅本机，跨设备不同步**（FR-060） |
| 默认启动分组视角 | 重启后按设定视角进入；**仅本机，跨设备不同步**（FR-060） |
| **清除全部数据**（V1） | 经不可关闭门闩 + 二次确认后，密钥/Keychain/同步元数据清空；**恢复购买**仍可用（FR-061、SC-014）。文案须告知同步设备也会被清 |
| 用量自动刷新间隔 | 见 §4.3、§4.6（**V2**，V1 跳过） |
| 货币与汇率 | 切换 CNY 后金额按用户维护的汇率换算，且标注为换算值（**V2**） |
| 单价规则管理 | 可增改；见 §4.5（**V2**） |
| 三类提醒开关 | 关闭后不再收到对应通知（**V2**） |

### 6.1 偏好同步边界（FR-060 / SC-013）

1. 设备 A 将外观改为深色，设备 B 保持跟随系统。
2. 等待 CloudKit / 钥匙串同步后 → **期望**设备 B 外观**不变**（设备偏好不同步）。
3. 设备 A 将「取出密钥明文的验证方式」改为「不验证」。
4. 同步后 → **期望**设备 B 的验证方式亦为「不验证」（安全偏好同步）。

## 7. 安全验收清单（逐条必查）

| 检查 | 方法 | 期望 |
|------|------|------|
| 明文不入 SwiftData/CloudKit | 检查本地 store 文件与 CloudKit Dashboard | 无任何明文字段 |
| 明文不入日志 | 全量搜索日志输出 | 无明文，无「前 N 位」拼接 |
| 明文不入崩溃报告 | 触发一次崩溃 | 无明文 |
| `maskedHint` / `secretLength` 为空 | 检查存储值 | 两字段均为 nil，无末位片段 |
| Keychain 未设置 ACL | 代码审查 `KeychainStore` | **无** `kSecAttrAccessControl`（否则与同步互斥，必然失败） |
| 管理凭证可被后台读取 | 代码审查 | 使用 `AfterFirstUnlock`，且读取路径**不经过** `RevealGate` |
| 管理凭证门闩不可关闭 | 尝试在设置中关闭 | 无此选项 |
| 加密备份门闩不可关闭 | 同上 | 无此选项 |
| 全部请求 HTTPS | 抓包 | 无 HTTP |
| 文案不夸大安全性 | 通读所有安全相关文案与商店描述 | **不出现**「系统级强制」「无法绕过」等表述（plan.md Constitution Check） |
| 高权限凭证风险已披露 | 检查配置界面 | 明确告知 Admin/Management Key 的权限范围与风险 |

## 8. 本期已知限制（验收时不作为缺陷）

- **应用层门闩弱于系统级 ACL**：为换取 iCloud 同步的必然取舍，已在产品内披露。（research §1、DC-006）
- **后台刷新时机不可控**：系统调度，非缺陷。（research §7）
- **DeepSeek 无按密钥用量**：平台能力所限，产品如实告知。（platform-adapters §4.2）
- **OpenAI / Anthropic 不提供按密钥费用**：只能估算。（platform-adapters §2.1、§3.2）
- **Claude 缓存 token 不计入费用估算**：口径已标注。（platform-adapters §3.2）
- **无中转功能**：属阶段三，本期界面不应出现任何中转入口。（spec US7）
