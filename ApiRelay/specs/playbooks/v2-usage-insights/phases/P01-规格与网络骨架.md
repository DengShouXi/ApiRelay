# V2 · Phase 1 — 规格与网络骨架（实现提示词）

---

请启动 **V2**，本阶段只做规格落地与网络层骨架，**不要**实现完整用量 UI。

## 必读

- `ApiRelay/specs/ROADMAP.md` V2
- `001-key-vault` 的 data-model / contracts（继承，只做 additive）
- 宪法：新增平台 = 新增 Adapter，不改既有 adapter 上层 protocol

## 本阶段目标

1. 若尚无：创建 `specs/002-usage-insights/` 增量 spec / plan / tasks（可用 Spec Kit 命令），范围对齐 ROADMAP。
2. 创建 `Data/Network/`：`HTTPClient`、错误分类、`PlatformAdapting` 协议落地位置。
3. 创建 `Business/Provider/`、`Business/Insights/` 目录与对外 `*Serving` 协议骨架。
4. 后台刷新相关 entitlements / `BGTaskScheduler`（V1 故意未加的那些）。
5. 确认仍遵守：UI 不直接碰 URLSession；Adapter 为 `actor`。

完成后勾选本阶段 tasks；汇报目录与协议清单。


---

## 本阶段完成后（这段不要复制进实现对话）

实现 Checkpoint 通过后，按顺序另开操作：

1. 打开并粘贴提示词：`../05-annotate-branch.md`（更新 `BRANCHES.md` 英+中备注）
2. 再打开并粘贴提示词：`../15-phase-push.md`（在分支 `v0.2` 上 commit，打 **tag `v0.2.1`**，再 `git push`）

说明：第三层是 **tag `v0.2.1`**，不是新建分支；人继续留在 `v0.2` 做下一 Phase。
