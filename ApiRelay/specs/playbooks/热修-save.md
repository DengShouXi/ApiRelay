# 上架后热修 — 保存并上传提示词

> **何时用**：某个小迭代（如 `v1.13`）**已经关账**，并且商店那一包已经打了 tag（如 `release/1.0.0`），现在只是修 bug / 改文案，不是开新的 P0N。  
> **上传顺序唯一正文**：[`ZL01_具体说明/09-上传流程.md`](../../../ZL01_具体说明/09-上传流程.md) §1（对照规格 → 同步说明 → 提交 A/B → 快进大阶段 tip）。本文件**不复制** A/B 步骤和记账文件清单。  
> **分支权威**：[`BRANCHES.md`](./BRANCHES.md)「分支 vs tag」+ 保护约定。中文说明：[`重要说明/分支与版本.md`](./重要说明/分支与版本.md)。

用户说「上传」即可，不必把本文件贴进对话，也不必再念「按热修-save」。  
进入开分支之前，MUST 已按 `09` §1 做完对照规格与同步 `ZL01`。若本次为对齐改了代码，`selfcheck` 红线不过则不要进入 commit。

对齐规格所必需的改动允许在「上传」对话里做完（见 `09` §1.1）；禁止顺手重构。不要送审、不要打新 tag。

---

请按 `ZL01_具体说明/09-上传流程.md` §1 做完对照与同步后，再按本文件选择热修分支并遵守禁止项。真正的两次提交与记账只执行 `09` §1.3。

## 固定目标（写错视为失败）

先看当前 HEAD 所在的**已冻结**小迭代（例：现在停在 `v1.13`，与 tag `release/1.0.0` / `main` 同 tip），然后：

| 项 | 必须使用的值 |
|----|----------------|
| **本次上传的 Git 分支** | `v{阶段}.{小迭代}.{热修}`（例：冻结的是 `v1.13` → 开 **`v1.13.1`**；已有 `.1` 则 `.2`） |
| 大阶段 tip | 对应 `v1` / `v2` / `v3`（只 fast-forward 前进） |
| 远程 | `origin` |
| 台账 | `ApiRelay/specs/playbooks/BRANCHES.md`（English → 简体中文）。**何时改、改哪几列，见 `09` §1.3 / §4** |
| 商店版本 | **本次默认不改** `MARKETING_VERSION` |
| 上架 tag | **本次不打**；已有的 `release/N.0.0` 不准移动 |

先例：`v1.11` 关账后开 `v1.11.1`。

## 禁止（常见误操作）

- 在已冻结的 `v1.13`（或任何已关账 `v1.N` / `plan.N`）上继续 commit 再 push，盖掉旧 tip。  
- 新建 **分支** `release/1.0.0` 或 `release/1.0.1`（`release/*` 只允许当 **tag**；`release/1.0.0` tag 已经存在）。  
- 把 `v1.13` 改名为 `release/1.0.0`。  
- 开 `v1.14` 来装这次修 bug（那是下一整块产品小迭代的名字，不是热修）。  
- force push；移动已有 tag；未另授权就把 `main` 推到热修 tip。  
- 把 `ZL03_原始素材/相关展示截图/`、`ZL03_原始素材/icon素材/`、`DebugScratch/`、`build/`、密钥、`.env`、含真实密钥的截图加进提交。
  （`ZL03_原始素材/README.md` 可以入库；整棵素材二进制不要进。）  
- 打开某个 `P0N-save.md` 冒充新 Phase。  
- 改宪法 / `spec.md` / `ROADMAP.md`（决策没变就不动）。  
- 用 `git add .` / `git add -A` 或任何会吞进 `tools/` 的通配。  
- 把 A/B 步骤改成一次提交，或再为记账提交追加第三次。

## A. 开热修分支（带着未提交改动离开冻结 tip）

```bash
git rev-parse --abbrev-ref HEAD    # 若是已冻结的 v1.13 / main，不要在上面 commit
git checkout -b v1.13.1            # 分支名按上表替换；工作区改动一起带走
```

若已经在正确的热修分支上（例如正在 `v1.13.8` 做本线工作），**不要再 `checkout -b`**，也不要另开 `v1.13.9` 或 `v1.13.8.1` 来装这次上传。直接按 [`09` §1.3](../../../ZL01_具体说明/09-上传流程.md#save-step-git) 提交。

## B. 提交、记账、快进

完整步骤只在 [`09` §1.3](../../../ZL01_具体说明/09-上传流程.md#save-step-git) 与 [§4](../../../ZL01_具体说明/09-上传流程.md#upload-notes)。本页不复写文件清单。

做完后确认：未 `git push origin v1.13`（冻结 tip）；未改 tag；未默认 push `main`；未 force push。

## C. 完成汇报

- 热修分支名与远程是否已有内容提交  
- 冻结未动：对应冻结 tip、tag `release/1.0.0`、（默认）`main`  
- 大阶段 tip 是否已按 `09` 前进  
- 确认：未新建 `release/*` 分支；未改 `MARKETING_VERSION`；未打新 tag；未 force push  
- 下次若要再送审：另授权 bump 商店 **1.0.1**、Archive，再考虑 ff `main` 并打 tag `release/1.0.1`
