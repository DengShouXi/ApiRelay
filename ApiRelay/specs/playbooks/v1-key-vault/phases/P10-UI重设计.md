## 一页设计原则（锁定稿）

### 1. 导航外壳（相对旧稿的变更）

- **一级导航 = 底部 4 Tab**，顺序固定：按平台 → 按使用方 → 回收站 → 设置。
- 「按平台」「按使用方」共用同一套列表能力，只换分组；回收站、设置各是独立页（可仍是现有 sheet/页，但入口升为 Tab）。
- **不要**再把回收站 / 设置只藏在「⋯」里当唯一入口；「⋯」只放更次要的（如使用方工具管理）。
- Mac / iPad：同一套 4 项信息架构；形态可用系统 Tab，**不**为本迭代单独做 iPad 双栏。避免使用仅 iOS 可用的 API 而不加平台分支（例如勿无条件使用 `.insetGrouped`）。

### 2. 密度（主内容区）

- 主区用系统 `List` 中等密度，**不要** App Store Today 式大卡片 / 仪表盘。
- 一行一件事：密钥行 = 名称 + 掩码 + 必要徽章 + 主操作（**复制优先**）。
- 「+」仍是添加主行动点；与右上角账号、左上角「⋯」分工清楚。

### 3. 层级

- **L0** 底部 Tab（含双视角两个 Tab）。
- **L1** 分区头 = 上游账号或使用方工具。
- **L2** 密钥行；共享标记、「本机暂无明文」为行级状态。
- 录入 / 指派 = sheet；设置已是 Tab，不再从首页再套一层「打开设置」当主路径。

### 4. 空态

- 无账号 / 无工具等：文案与主按钮随当前 Tab（视角）变，禁止通用「暂无数据」。
- 空态只给 **一个** 主按钮（加账号 / 加工具）。
- 回收站空：单独空态文案，主按钮可以是「完成/返回」或引导去列表，不与加密钥混淆。

### 5. 主色 / 系统色

- 只用系统语义色：`.primary` / `.secondary` / `.tint` / `.destructive`。
- Tab 选中态用系统 tint（类似 App Store 底栏选中变色）。
- 危险操作用 destructive；同步未就绪用 secondary，不当成 error。

### 6. 主路径步数

- 录入一把密钥并出现在列表：≤ 5 次有意图点击。
- 复制明文：≤ 2 次点击 + 1 次生物识别。
- 切双视角：点另一个底部 Tab，**1 次**。
- 进回收站 / 设置：各 **1 次** Tab。
- VoiceOver / Dynamic Type 不回退；4 个 Tab 均有可读标签。

### 7. 非目标

- 不改门闩 / Keychain / Data / 业务 protocol。
- 不做独立「登录注册」；右上角账号是示意入口（可后续接 Apple ID / iCloud 说明，本期可先占位或打开系统账户相关说明）。
- 不做 iPad 专属双栏、不做 Mac 原生 target、不做用量/关系图（V2）。
- **不**把主列表改成 Today 大卡片营销墙。

## 硬约束

- 一次对话只改 UI 相关；发现顺路可优化只报告不动手。
- 过大 `VaultHomeView` 按「Tab 壳 / 列表 / 分区头 / 空态 / sheet」拆子 View；共享样式进 `UI/Shared`。
- 编译目标含 Mac Catalyst：List 样式等 API 必须双端可编译。
