## Stage1 当前路径（摘要）

```text
v1.13 已关账 + tag release/1.0.0（商店 1.0.0）
  → v1.13.1 已关账（热修快照）
  → v1.13.2 ← 当前工作分支（上架后热修；不盖 v1.13 / v1.13.1，不开 release/* 分支）
  →（可选）20-push → 30/40 进 v2 实现
```

大阶段 tip `v1` 跟随最新热修；`main` 与 tag `release/1.0.0` 停在商店 1.0.0 不动。

详情见 [阶段1-密钥库.md](./阶段1-密钥库.md)、[分支与版本.md](./分支与版本.md) 与 [`../v1-key-vault/00-README.md`](../v1-key-vault/00-README.md)。

## 硬规则（摘要）

- 小阶段写完 → 打对应分支并上传（`plan.N` / `v1.N` / `v2.N` / `v3.N`）。  
- 已关账 / 已上架后的修 bug → [`../热修-save.md`](../热修-save.md)（例：`v1.13.1`），**不要**盖冻结 tip，**不要**开 `release/*` 分支。  
- **禁止**再新建旧名 `v0.0.*` / `v0.1.*` / `v0.2.*` / `v0.3.*`。  
- 改分支规则只改 `BRANCHES.md`；改阶段范围只改 `specs/ROADMAP.md`。  
- **不要**在本目录复制一整份 BRANCHES / ROADMAP。  
- Stage1 商店材料在 **P13**；发布动作在 **T062**（`12-release-T062.md`），二者不要混做。
