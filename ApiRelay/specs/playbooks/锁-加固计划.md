## 0. 最终判断（先读）

当前锁**已经比上一版加固很多**（单调时钟、会话闸、降级须落盘成功、写入口收口、快照与计时拆开、认证中不当闲置、iPadOS 26 补了 Key / `activeAppearance`），**仍不能关账发布**。

Wave 3 之后还欠：

1. 三端真机矩阵未勾（Wave 4）。

成熟密码库也**没有**「做一次永远不再出问题」的锁。1Password、Apple 密码、Bitwarden 都是：**进程级一座保险库锁 + 每扇窗自己的隐私遮罩 + 系统升级后重跑矩阵**。本计划按这个模型收口，不发明「每扇窗各自解锁」的第二套保险库。

## 1. 向成熟方案对齐（决定，不是口号）

| 能力 | 成熟密码库怎么做 | 本项目现在 | 本计划采用 |
|------|------------------|------------|------------|
| 会话锁 | 整个进程一座库，解锁一次全窗生效 | 全局 `AppLockSession` + `SessionLockBox` | **保持进程级**。不得做成窗 A 锁、窗 B 仍能复制。 |
| 隐私遮罩 | 每扇窗自己的快照 / 模糊 | 所有 scene 汇总后，一个控制器盖所有窗 | **每扇窗独立遮罩**；锁态仍全局。 |
| 台前同组失焦 | 一般不立刻锁库；内容常仍可见 | 不锁、不盖白屏（体验对齐） | **不锁、不计时、不弹验证、不盖白色锁屏**。轻量模糊**本轮不做新设置**。 |
| 真离开 / 换组 / 后台 | 开始闲置计时或立即锁；切换器无明文 | 与失焦混在同一套 presence | **遮罩与计时拆开**（见状态表）。 |
| 系统验证 | 同时只有一个；失焦要收掉盖在别人头上的框 | `RevealGate` 已有请求编号；iPad 26 用 Key/外观补 | **规则写死**：验证框在时不算「去了别的 App」；同组失焦必须 `cancel`。 |
| 设置降级 | 未确认成功前界面不降级 | 先改内存再异步 `persist` | **先保存成功，再改锁态与启动缓存**。 |
| 业务门禁 | 锁住后写操作全部拒绝 | 密钥新建/复制/备份有闸；使用方与回收站等没有 | **Business 写路径统一 `rejectIfSessionLocked`**。 |
| 发布 | 真机矩阵，系统大版本重跑 | 矩阵存在，三端全模式未勾 | 自动化绿 **不能**代替三端矩阵。 |

**明确不做（本轮与下一轮都不要混进来）：**

- 每扇窗独立解锁 / 独立自动锁到期。  
- 用 `sendEvent` 钩子猜主窗（私有、易碎）。  
- 为 Spaces / 外接屏去用私有 WindowServer API。  
- 录屏 DRM、截屏系统级拦截（系统做不到就披露，不假装）。  
- 同组失焦默认模糊（要做须另开设置项，本轮不增开关）。  
- 顺手改 CloudKit 同步架构。

## 3. 统一行为规格（一份表，禁止页面特例）

每个**窗口**先落入下列状态；**会话锁 / 计时**只由「全进程汇总」决定。

### 3.1 窗口状态

| 状态 | 怎么认（实现允许用测试注入，禁止猜） | 该窗快照遮罩 | 该窗白色锁屏 | 系统验证 |
|------|----------------------------------------|--------------|--------------|----------|
| A 正在操作 | 本窗 `foregroundActive` 且（Key 或 `activeAppearance == .active`） | 关 | 仅当**全局已锁** | 仅当全局已锁且本窗是操作窗；Mac 仍须点「解锁」 |
| B 可见未聚焦 | 台前同组 / 分屏：窗仍 `foreground*`，但无 Key 且外观 inactive | 关（D2） | 关 | **必须 cancel** 进行中的框 |
| C 系统验证接管 | LA / 主密码框在前；可能抢走 Key，外观仍 active | 关 | 若已锁则保持解锁层 | **禁止**当成 B 去 cancel |
| D 被完全遮挡但仍属本空间 | 尚无稳定公开 API；**本轮按 B 处理**，外接屏手测记录，不写死「锁」 | 同 B | 同 B | 同 B |
| E 其它台前组 / 其它 Space / 最小化 / 隐藏 | 该窗 scene `background` 或离屏 | **开**（若开了切换器隐藏） | 不画锁图标（那是全局的） | cancel（若这是最后一扇操作窗） |
| F 真进后台 | 应用 `background`，没有任何前台 scene | 开 | 全局按计时/立即锁 | cancel |
| G 设备锁屏 / 睡眠 | 能收到的系统通知当 F；收不到的不假装能锁 | 尽力 | 醒来按 F 的到期结果 | — |

### 3.2 进程级会话锁（D1）

用**最「在场」的那扇窗**汇总，而不是「任意一扇 foregroundActive 就当人在用」掩盖另一扇已经离屏。

| 汇总 | 自动锁计时 | 会话锁 |
|------|------------|--------|
| 至少一扇处于 A 或 C | 停止 / 不开始 | 保持当前（已锁就仍锁，未锁保持未锁） |
| 最前是 B 或 D，没有任何 A/C | **不开始**（D2） | 不锁 |
| 所有窗都是 E/F/G | **开始**；「立即」则静默锁 | 到期或立即 → 锁 |

解锁一次：所有窗共享同一 `isSessionLocked`。  
揭开快照：只揭**正在操作的那一扇**；已锁时揭开是为了点到解锁层，不得把另一台显示器上的窗也揭成明文。

### 3.3 与现码的差距（开工对照）

| 规格 | 现码 |
|------|------|
| 每窗遮罩 | `WindowPrivacyReducer.reduce` + 按 scene 盖快照；解锁层只在操作窗 |
| 失焦 ≠ 离屏 | 已有 `onScreenIdle`；idle 不留快照，离屏窗单独盖 |
| 验证框在时不算离开 | 夹具含 `authenticationInProgress`；C 未确定离屏时视为正在操作 |
| 未知信号 | `PresenceSignal.unknown`；未知 ≠ 离屏。本 target 无公开 `appearsActive` |
| 保存失败回滚 | persist 成功后才改锁态（Wave 1） |
| 写操作全闸 | 使用方 / 回收站 / 指派 / 排序已过闸（Wave 1） |

## 4. 代码实现计划（四波，每波可单独测试）

原则：先补闸和时序，再拆窗口对象；每波改动限制在锁模块 + 对应测试。宪法 / FR 只在 Wave 1 开工时按已签字的 D1–D4 补编号，**本页不预占 FR 号**。

### Wave 1 — 关 P0 失败放行 + P1 门禁漏网 + 快照/计时拆开（仍一个控制器）

**目标：** 不引入「每窗一个 AppPrivacyController」，先把能在单测里钉死的漏洞补上。

| 项 | 改哪里 | 做法 | 不做 |
|----|--------|------|------|
| 1.1 安全降级事务 | `SettingsView.persistSyncedPatchAsync`、`PreferencesService` | 降低等级：验证通过后 **只 persist**；成功回调里才改 `@State`、`applyLivePreferences`、`AppLockLaunchCache`。失败：界面保持旧值，提示失败，缓存不写关锁。提高等级仍可先改内存（失败不降低安全）。主线程仍不得 `await` SwiftData save。 | 不改 CloudKit 冲突合并策略（那是 v1.14） |
| 1.2 业务闸收口 | `KeyVaultService`、`ConsumerToolService`、`RecentlyDeletedBatchService` | 所有**用户发起的写**（含恢复、永久删、指派、排序、使用方 CRUD）先 `rejectIfSessionLocked`。后台 `purgeExpired*` 保持不弹门闩，但若会话锁住则跳过本轮清扫（避免锁下改数据）。读列表可以继续（列表本就无明文）。 | 不在 Data/Repository 层加锁 |
| 1.3 快照 ≠ 计时 | `AppLockSession` 拆两个意图；`AppPrivacyController.handleWillResignActive` | **失去活动**：若开了切换器隐藏 → 立刻上快照遮罩（可挡住切换器那一帧）。随后若判定为 B 同组闲置 → **马上摘罩**（允许极短闪，但不得留白锁屏）。**确认离屏**才 `noteDidEnterBackground` 计时/立即锁。控制中心：resign 后未 background 又 active → 摘罩、不计时。 | 本波仍可「盖所有窗」；Wave 2 再按窗 |
| 1.4 认证中 | `AppPrivacyController` + `RevealGate` | `isUnlocking` / evaluate 进行中 → 强制视为 C，不得走 B 的 cancel。同组已确认 B → 必须 cancel，避免框留在 Safari 上。 | 不改门闩档位语义 |

**完成定义（机器）：** 见 §5.1。本波结束后仍**不得**声称锁已关账（多窗口结构还在）。

### Wave 2 — 窗口级隐私，进程级锁（关 P0 多窗口）

**目标：** 一个全局锁，多套窗口遮罩。

| 项 | 做法 |
|----|------|
| 2.1 生命周期所有权 | 应用级通知只由 **一处** 听（现有 `AppPrivacyController` / AppDelegate），`ContentView` **停止** 每份副本都 `onReceive` 同一组 `UIApplication` 通知。 |
| 2.2 `WindowPrivacySurface` | 每个 `UIWindowScene`（或每个 `UIWindow`）独立：是否显示快照层、是否显示解锁层（解锁层跟全局锁走，但只出现在需要点击的那一扇）。 |
| 2.3 汇总函数可测 | `reduce(windows:) -> (presence, startTimer, whichWindowsCovered)` 纯函数，测「窗 A 在当前 Space、窗 B 在另一 Space」。 |
| 2.4 揭罩 | `didBecomeActive` 只摘**当前 scene** 的快照；禁止一次摘掉所有显示器上的罩。 |

**依赖：** Wave 1 的「快照 ≠ 计时」已落地，否则按窗拆会把两种时序再缠一次。

**完成定义：** §5.2。外接屏 / 多 Space 仍欠真机。Wave 2 机器侧已入库。

### Wave 3 — 台前 / iPadOS 26 信号收口（关 P1 经验性判断）

| 项 | 做法 |
|----|------|
| 3.1 信号清单写进测试夹具 | scene `activationState`、`applicationState`、`isKeyWindow`、`activeAppearance`、（若 SDK 对本 target 可用）`appearsActive`。缺的信号在夹具里标「未知」，实现按保守：未知 ≠ 离屏。 |
| 3.2 C 与 B 的回归 | 单测：验证进行中抢走 Key 不得 cancel；同组失焦无验证框不得锁。 |
| 3.3 矩阵补行 | 更新 `锁-验收矩阵.md`：iPad 台前同组点 Safari、换组、本 App 多窗一前一后、外接屏；Mac Spaces / 多显示器 / Mission Control。 |

**本波不新增「失焦模糊」设置**（D2）。Wave 3 机器侧已入库。

### Wave 4 — 发布门禁（无新功能）

- 全量单测 + `selfcheck.sh`。  
- §6 三端矩阵由产品负责人勾。Agent 不能代勾。  
- 未勾完：不得说锁已收口，不得捆进送审包当「锁已修完」。
