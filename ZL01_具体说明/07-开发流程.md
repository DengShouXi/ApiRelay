## 二、按「分支上传」主线的时间顺序

对齐 [`BRANCHES.md`](../ApiRelay/specs/playbooks/BRANCHES.md)：**小阶段写完 → 对应 save → 打小迭代分支并上传**；已关账后修 bug → [`热修-save.md`](../ApiRelay/specs/playbooks/热修-save.md)。

```text
1. 定范围 / 改设计
   → A：ROADMAP、spec、plan…（± 宪法）

2. 开或切到对应小迭代分支
   → 命名与当前 tip：见 08；权威 BRANCHES

3. 按该阶段 playbook 做 P0N
   → A：specs/playbooks/v0-planning | v1-key-vault | v2-… | v3-…
   → 代码：ApiRelay/ApiRelay/（见 02）

4. 小阶段完成 → 打分支并上传
   → 规划：v0-planning/phases/P0N-save.md → 分支 plan.N
   → Stage1：v1-key-vault/phases/P0N-save.md → 分支 v1.N
   → Stage2/3：对应目录 P0N-save → v2.N / v3.N
   → 已关账/上架后修 bug：热修-save.md → v1.13.2 这类热修分支
   → 同时更新 BRANCHES（English → 简体中文）

5. 大阶段 tip（v1 / v2 / v3）只 fast-forward
   → 细则见 热修-save / 各阶段 15-phase-push；口令见 08

6. 若进入系统整改（事故、验证能力补齐）
   → B：ZL02 该次问题的 00-总览 → 按序 H1、H2…
   → 改需求仍回步骤 1，不要把 FR 抄进 ZL02
```

中文流程总入口（可选）：[`重要说明/索引.md`](../ApiRelay/specs/playbooks/重要说明/索引.md)。
