<h2 id="how-to-use">使用方法</h2>

| 场景 | 执行方式 |
|---|---|
| 本项目新增或重排说明页 | 先读配置块，再按 §2～§9 编写，最后按 §13 验收 |
| 迁移到新项目 | 复制本页，只改 §1，再执行 §11 |
| 不需要 Cursor 对话记录 | 将对话模块设为“关闭”，不引入相关文件 |
| 需要打开 Cursor 历史对话 | 将对话模块设为“开启”，安装 §10 中的工具包 |

**三条总则：**

1. **一条规则只写死一处。** 正文只链接权威页，不到处复制。
2. **项目差异只进配置块。** 项目名、说明夹、入口页和可选模块不散落成通用硬编码。
3. **改完必须验收。** 不以“看起来正常”代替链接、锚点和实际点击检查。

<h2 id="document-architecture">§2 · 文档架构</h2>

说明体系按**角色**设计，不按当前想到的文件随意堆叠。

| 角色 | 回答的问题 | 常见内容 |
|---|---|---|
| 入口 | 新来的人或 AI 先看什么 | 阅读顺序、当前状态、权威路径 |
| 地图 | 东西在哪 | 仓库地图、代码地图、模块关系 |
| 边界 | 什么可改，什么不能改 | 路径红线、安全限制、数据边界 |
| 标准 | 以什么为准 | 需求、设计决策、工程准则 |
| 流程 | 事情怎么做 | 开发、测试、发布、分支和回滚 |
| 历史 | 已经发生过什么 | 上传记录、对话索引 |
| 格式 | 文档怎样保持一致 | 本页和专项格式页 |

<h3 id="flat-or-layered">§2.1 · 平铺还是分层</h3>

- 文档较少、一屏能辨认时平铺。阅读顺序以入口页为准；序号与阅读顺序不一致时，在配置块写明，不为表面一致改文件名。
- 文档较多并形成稳定领域时分层，每个子目录都设自己的入口页。
- 不为了收藏一两个文件新建子目录。
- 目录模式写入配置块后统一执行，不一半平铺、一半隐藏分层。

<h2 id="file-naming">§3 · 命名与序号</h2>

| 位置 | 写法 | 示例 |
|---|---|---|
| 文件名 | `NN-标题词.md` | `03-路径红线.md` |
| H1 | `# NN · 标题词` | `# 03 · 路径红线` |
| 文内称呼 | 短名加完整链接 | `[03](./03-路径红线.md)` |
| H2 | `§N · 标题` | `§1 · 适用范围` |
| H3 | `§N.N · 标题` | `§1.1 · 安装` |
| H4 | `§N.N.N · 标题` | `§1.1.1 · macOS` |
| 最下层无序内容 | Markdown 小点 | `- 相对路径` |
| 最下层有序步骤 | 阿拉伯数字 | `1. 确认`、`2. 修改`、`3. 验收` |

- 标题词只回答一件事，使用读者会搜索的词。
- 文件名、H1 和入口页短名必须是同一组词。
- 已被引用的文件不随意改序号或文件名。
- 新页按角色插入，不是看见空号就随意填入。
- 项目已有稳定命名体系时，在配置块写明并保留，不为表面一致批量改名。

<h2 id="page-hierarchy">§4 · 页内层次</h2>

```text
文档标题（不编号）
├── 文首引用块（上一页 / 下一页 / 总入口，可选）
├── 返回总入口（入口页以外；不编号）
├── 目录（不编号，固定 id="toc"）
└── H2 = §1 · 一级章节
    └── H3 = §1.1 · 二级章节
        └── H4 = §1.1.1 · 三级章节
            ├── 小点 = 无先后关系的说明
            └── 1. 2. 3. = 有先后关系的步骤
```

<h3 id="page-toc-rule">§4.1 · 目录与返回目录</h3>

- **每一份说明文档都必须有目录，不因篇幅短而省略。**
- 目录放在文首说明和导航之后、第一节正文之前，标题固定写成 `<h2 id="toc">目录</h2>`。
- 目录至少列出全部 H2，并与正文顺序一一对应；需要列出 H3/H4 时，必须按正文层级缩进。
- 每个目录项都链接到正文标题的显式 `id`，例如 `[§1 · 适用范围](#scope)`；禁止依赖预览器自动生成的标题 slug。
- 每个 H2 正文块的末尾都必须写 `[↑ 返回目录](#toc)`，最后一节也不能省略。
- “返回目录”应位于本节全部正文之后、下一条大分隔之前；目录块自身不写“返回目录”。
- 已有文档使用稳定的旧目录 id 时可以保留，但目录链接和所有“返回目录”必须指向同一个真实 id。

```html
<h2 id="toc">目录</h2>

- [§1 · 适用范围](#scope)
- [§2 · 使用方法](#usage)

<h2 id="scope">§1 · 适用范围</h2>

正文内容。

[↑ 返回目录](#toc)
```

- 一篇只有一个 H1，正文标题按 H2 → H3 → H4 递进，最深到 H4。
- 没有内容不建空标题，不为不确定的未来预留空壳。
- 目录与全部 H2 一一对应；新增、删除、改名或重排 H2 时，必须同步更新目录。
- 最下层没有先后关系时用小点；有明确先后关系时用阿拉伯数字 `1. 2. 3. …`。
- 有序步骤较长或包含多个阶段时，应拆成小节，避免列表层级过深。
- 小点和阿拉伯数字列表都不进入目录，不写入锚点 id。

<h3 id="return-to-entry">§4.2 · 返回总入口</h3>

入口页以外的每一页，必须能从本页跳回总入口。总入口文件名、序号和标题词从 [§1 · 项目配置块](#project-profile) 读取。

**固定句式（当前项目）：**

```markdown
[← 返回 00 · 从这里开始](./00-从这里开始.md)
```

迁移后只替换花括号里的三处，句式不动：

```markdown
[← 返回 {序号} · {标题词}](./{入口文件名})
```

**摆放：**

```text
文首引用块（上一页 / 下一页 / 总入口，可选）
大分隔 ━━━
[← 返回 00 · 从这里开始](./00-从这里开始.md)
<h2 id="toc">目录</h2>
```

- 写在文首大分隔之后、目录标题之前，单独一行。
- 引用块里可以再写「总入口：」，**不能**只写在引用块里、目录上方没有这一行。
- 入口页本身不写“返回自己”。
- 这一行不进入目录，不另加锚点 id。

**和「返回目录」不要混：**

| 链接 | 箭头 | 跳到哪 | 出现位置 |
|---|---|---|---|
| 返回总入口 | `←` | 总入口页（离开本页） | 目录正上方，每页一行 |
| 返回目录 | `↑` | 本页目录 | 每个 H2 正文末尾 |

**禁止：**

- 改成「返回首页」「回到导航」「返回目录页」等另一套文案。
- 把 `←` 改成 `↑`，或把这一行写进目录列表。
- 链接到本页 `#toc` 冒充返回总入口。
- 写本机绝对路径或 `file://`。

```html
[← 返回 00 · 从这里开始](./00-从这里开始.md)

<h2 id="toc">目录</h2>
```

<h2 id="links-and-paths">§5 · 链接与路径</h2>

| 目标 | 写法 | 示例 |
|---|---|---|
| 本页落点 | 显式 `#id` | `[配置](#project-profile)` |
| 同目录文件 | `./文件名.md` | `[入口](./00-从这里开始.md)` |
| 其他目录 | 相对当前文件的路径 | `[规格](../specs/spec.md)` |
| 外部网页 | 完整 HTTPS 地址 | `[文档](https://example.com/docs)` |
| Cursor 历史对话 | §10 规定的受控链接 | 不使用裸 UUID |

**文首导航：** 返回总入口的句式和摆放只认 [§4.2](#return-to-entry)。引用块可另写上一页 / 下一页 / 总入口；分层模式优先写上级入口。目录上方那一行仍然必写。

**禁止：**

- 不写任何本机绝对路径或 `file://` 链接。
- 不写缺少协议和语义的裸 UUID。
- 不复制浏览器地址栏中的临时预览 URL。
- 不猜测自动 slug；重要跳转使用显式锚点。

<h2 id="explicit-anchors">§6 · 显式锚点</h2>

重要落点使用显式 `id`，不依赖不同预览器的自动标题 slug。

```html
<h2 id="toc">目录</h2>
<h2 id="scope">§1 · 适用范围</h2>
<h3 id="install-macos">§1.1 · macOS 安装</h3>
[↑ 返回目录](#toc)
```

- 新项目推荐小写 ASCII 字母、数字和短横线，如 `install-macos`。
- id 表达语义，不包含顿号、间隔号和空格。
- 同一文档内必须唯一。
- id 发布后视为稳定接口；改 id 必须同步修改全部入链。
- 旧项目已有稳定中文 id 时不批量改名；新增 id 再执行新规则。

<h2 id="tables-and-status">§7 · 表格与状态</h2>

- 表格只用于需要横向对照的数据；连续说明用段落或列表。
- 每列只表达一种维度，表头不用“其他”“备注 2”等含糊名称。
- 单元格内多个独立项用 `<br>` 换行，不用“同上”。
- 有序数据写明排序依据，如时间、优先级或产生顺序。
- 状态图例在权威位置定义一次，本通用页不预设某一业务的颜色含义。
- 状态不能替代语义：“对话完成”不等于“子任务完成”。

<h2 id="separators">§8 · 分隔与可读性</h2>

| 场景 | 推荐写法 |
|---|---|
| 文首导航、目录和 H2 大段之间 | 大分隔 `━━━…` |
| 同一 H2 内的独立小块 | 小分隔 `┄┄┄…` |
| 普通段落 | 空行，不额外加线 |

- 同一项目只选一套分隔视觉，不混用多套实际同形的横线。
- 分隔只表示结构，不代替标题。
- 目标渲染器不适合 Unicode 分隔线时，在配置块替换整套风格，不在正文局部混改。

<h2 id="authority">§9 · 权威与去重</h2>

| 内容类型 | 权威位置 | 普通说明页的写法 |
|---|---|---|
| 治理方法 | `ZL00_项目总控/` | 只链接，不复制总纲 |
| 当前项目状态 | `ZL01` 的 `14` | 其他页只链接 14 |
| 产品需求 | spec / requirements | 摘要加链接，不复制整段需求 |
| 开发计划 | plan / roadmap | 说明入口，不另建第二份计划 |
| 分支和发布 | playbook / branch policy | 链接权威文件，不多页复制口令 |
| AI 执行约束 | AGENTS / rules / 铁律页 | 只指路，不改写成相似版 |
| 文档格式 | 本页 | 先改本页，再改已采用页 |
| 专项格式 | 专项格式页 | 只写比本页新增的规则 |

新增内容前先问“是否已有权威文件”。如果有，建立链接，不建立副本。

<h3 id="dialog-install">§10.1 · 安装与使用</h3>

- 同一台电脑只需双击工具包中的“一键安装或升级”，所有项目通用。
- 换项目不需要复制工具包、VSIX 或安装脚本，也不需要在项目终端执行命令。
- 打开 Markdown 后按 `Command + Shift + V`，只在标签以“Markdown预览 ·”开头的专用预览中验收。
- 专用预览默认显示在 Markdown 右侧；未保存的修改也必须实时刷新。
- 预览右上角必须显示“实时预览／正在刷新／已同步”状态，点击该状态可以切换“跟随当前 Markdown”。
- 跟随开启时，在文件栏或标签栏切换到另一份 Markdown，右侧预览必须同步切换；代码、图片和聊天不得改变当前预览。
- 新项目需要采用本规范时，在命令面板运行“Markdown 格式与预览：把通用格式要求复制到当前项目”；已有同名文件不得静默覆盖。

<h3 id="dialog-data-protocol">§10.2 · 最小数据协议</h3>

```html
<span id="stage-d1"><a href="cursor://xitong.apirelay-dialog-navigation/open?composerId=REPLACE_WITH_REAL_UUID">对话名称</a></span>
<a href="#stage-t1">子任务名称</a>
<span id="stage-t1">子任务正文</span>
<a href="#stage-d1">对话名称</a>
<a href="cursor://xitong.apirelay-dialog-navigation/open?composerId=REPLACE_WITH_REAL_UUID" title="打开「对话名称」；位置：中">中</a>
```

- 对话名称只显示名称，UUID 隐藏在链接内部。
- 位置只允许：`整段` / `前` / `中` / `后` / `前–中` / `中–后`。
- 对话名称链接和对应位置链接使用同一 composerId。
- 禁止 `[名称](uuid)`、裸 UUID、红色竖线和全部目标常驻黄底。
- Cursor 升级如果改变内部对话命令，只更新扩展适配层，不批量改文档。

完整对话规范以 §1 配置块登记的“对话格式页”为准。迁移后，业务字段和状态语义应放入新项目自己的对话格式页。

<h2 id="migration">§11 · 迁移流程</h2>

<h3 id="migration-before">§11.1 · 复制前</h3>

- [ ] 确定新项目的说明目录和唯一总入口。
- [ ] 确定平铺还是分层。
- [ ] 确定是否开启 Cursor 对话导航。
- [ ] 盘点新项目已有的 spec、plan、rules 和其他权威文件。

<h3 id="migration-after">§11.2 · 复制后</h3>

1. 替换 §1 的项目名、说明目录、总入口和格式页名。
2. 重填页面角色表，删除新项目不存在的页。
3. 按开关处理 Cursor 对话模块。
4. 为每份说明文档建立目录；入口页以外在目录正上方加入返回总入口，并在每个 H2 正文块末尾加入“返回目录”。
5. 在新项目总入口登记本页；文首导航只从配置块取值。
6. 执行 §13 完整验收。

<h3 id="migration-exclusions">§11.3 · 不得机械带走</h3>

- 旧项目名、绝对路径、分支名和产品版本号。
- 旧项目的文件数量和角色分工。
- 旧项目的状态颜色、业务词和历史结论。
- 旧项目的 composerId；对话 UUID 只在原 Cursor 历史存在时有意义。
- 旧项目的 AGENTS、rules 或安全授权。

<h3 id="migration-done">§11.4 · 迁移完成标准</h3>

搜索旧项目名、旧说明目录、绝对路径、旧项目专用文件名，以及 `REPLACE_WITH_REAL_UUID`、`TODO`、`TBD` 等占位符。通用协议的明确示例代码可保留占位符；项目配置和真实业务记录中的结果应为 0。

<h2 id="ai-protocol">§12 · AI 执行协议</h2>

1. 先读项目配置块，不把示例项目的文件名或路径当成新项目事实。
2. 查找 AGENTS、README、spec、rules 和其他权威页。
3. 列出将要变更的文件，不因格式整理顺手改业务内容。
4. 保留工作区中不相关的用户改动。
5. 实施后搜索旧项目名、绝对路径、重复 id、缺失锚点和占位符。
6. 逐项点击目录，确认到达正确章节；再逐项点击章节末尾的“返回目录”。
7. 实际点击跨文件链接；对话模块开启时再验收四种对话点击。
8. 用数量报告结果，如“重复 id：0；缺失目标：0；绝对路径：0”。

**可直接复用的任务语句：**

> 请按《通用格式要求》维护本项目说明文档。先读项目配置块和仓库现有权威文件，只修改本次范围。确保每份文档都有目录、目录能跳到全部 H2、入口页以外目录正上方能返回总入口、每个 H2 末尾都能返回目录。完成后检查文件名、H1、显式 id、相对链接、重复规则和迁移占位符，并报告数量化验收结果。

<h2 id="acceptance">§13 · 验收清单</h2>

<h3 id="acceptance-structure">§13.1 · 结构</h3>

- [ ] 配置块已改成当前项目，不存在未说明的旧项目名。
- [ ] 只有一个 H1，文件名、H1 和入口页短名一致。
- [ ] H1 到 H2 到 H3 到 H4 不跳级，没有空标题。
- [ ] 每份说明文档都有目录，目录和正文全部 H2 一一对应。
- [ ] 入口页以外，目录正上方有 `[← 返回 {序号} · {标题词}](./入口文件)`，句式与配置块总入口一致。
- [ ] 入口页没有“返回自己”。
- [ ] 每个 H2 正文块末尾都有“返回目录”，包括最后一节。
- [ ] 入口页已登记新页，不存在孤儿文档。

<h3 id="acceptance-links">§13.2 · 链接与迁移</h3>

- [ ] 内部链接使用相对路径，本机绝对路径数为 0。
- [ ] 重复 id 数为 0，缺失 `#id` 目标数为 0。
- [ ] 已逐项点击全部目录链接，均到达正确章节。
- [ ] 已逐项点击全部“返回目录”，均回到同一目录。
- [ ] 已点击目录上方的“返回总入口”，到达配置块登记的入口页。
- [ ] 至少一个跨文件链接已实际点击。
- [ ] 旧项目路径、分支、版本和 UUID 未误入新项目。
- [ ] 除明确标记的通用示例代码外，项目配置和真实记录中的 `REPLACE_WITH_REAL_UUID`、`TODO`、`TBD` 等占位符已处理。
- [ ] 非本次范围的用户改动未被覆盖或回退。

<h3 id="acceptance-dialog">§13.3 · Cursor 对话模块（关闭时跳过）</h3>

- [ ] 对话名称打开正确的真实历史对话。
- [ ] 对话表“蕴含的子任务”跳到子任务正文。
- [ ] 子任务表“涉及对话”跳回对话名称。
- [ ] 子任务表“在对话中的位置”打开同一真实对话。
- [ ] 页内跳转后只有本次目标黄底，没有红色竖线或多个常驻黄底。
- [ ] 对话表名称后可见 UUID 数为 0。

<h2 id="maintenance">§14 · 维护</h2>

1. 普通文档版式发生争议：先改本页通用核心，再改已采用页。
2. 项目名、目录、入口或模块改变：只改 §1 和直接受影响的导航。
3. 专项格式改变：改对应专项页，本页只保留模块开关和稳定接口。
4. 新增页：确定角色，建立目录、目录正上方的返回总入口、每节“返回目录”，登记到入口页，最后执行 §13。
5. 删除或改名页：先搜索全部入链，更新后再执行。
6. Cursor 升级导致历史对话失败：只维护扩展适配层，保留文档中的 composerId 和锚点。
7. 修改本页后全文搜索被替代的旧规则，不让新旧检查表同时存在。
