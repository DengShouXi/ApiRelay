<h2 id="doing">§2 · 正在做什么</h2>

本轮已完成密码与身份验证整体架构收口：保留现有六层方向（策略、认证请求、会话与隐私、凭据、受保护业务、存储与跨设备），不进行有数据迁移风险的热修式重写。本轮已补齐 session lease、精确 request scope、Preferences/Keychain/Repository/Clipboard 最终 commit、运行期补偿、`createKey` / `backupImport` 崩溃恢复 WAL、文件持久删除 journal 和共享 `StorageMutationGate`。全量清除在同一授权提交中封住新写，等待旧事务完成；中断后启动保持失败关闭，经设备主人继续删除，清除 journal 后才重开。最新自动结果与设备边界统一记录在 [`22 §8`](../ZL02_研发档案/第一阶段-密钥库/调整与优化/v1.13.9-身份验证四档与主密码调整/22-密码与身份验证整体架构审计与加固.md#8-验证记录)。

当前最新修复把“验证方式子页就地切换”和“iPad 真正离屏”收回同一边界：密码确认框挂在导航栈而非被遮住的根页，迟到认证受请求代次限制；生命周期观察在异步存储准备前武装，由 application + scene 两级确认、多窗口汇总和单轮去重决定立即锁定。Home 与控制中心首帧信号相同时，立即档同步放上临时隐私罩并启用可逆 authorization fence，在最多 2 秒的单调时钟观察内只接受严格离屏证据；真离开升格为正式 suspension，`didBecomeActive` 则立即取消并阻断迟到回调。启动 active 与 Cloud 安全偏好导入另由首次权威读取栅栏约束，不得提前重开授权。

Mac 隐私链专项把自动锁、切换遮挡、剪贴板自动清除和通用剪贴板作为同一条桌面隐私链治理：Mac 整个应用真实失焦即开始自动锁，立即档当场静默锁；全部窗口同步遮挡。只有本 App 发起的精确系统认证请求造成的短暂 resign 延后判断；认证结束后若仍在其他 App，必须补做离场、撤权和锁定。剪贴板以写入代次和 `changeCount` 防止旧计时器误删，0 秒真正立即清除，Catalyst `.localOnly` 失败也不回退普通剪贴板。原始 30/463 证据保留在 [`21`](../ZL02_研发档案/第一阶段-密钥库/调整与优化/v1.13.9-身份验证四档与主密码调整/21-Mac隐私生命周期与剪贴板系统核对.md)，但不代替当前快照回归。

`v1.13.10` 按“测试保护 → 机械拆分 → 单一状态来源 → 全量回归”完成结构阶段，四组自动结果共 627 项通过，关账 SHA 为 `8e6c221`。新独立 `v1.13.11` 只做购买权益：先固定用例，再审查原 `v1.13.9` 的未提交购买草稿，按需最小修复并验证 StoreKit、恢复购买、状态查询失败和免费额度；原草稿与混杂的 Xcode 差异只作只读参考，不复制或顺手清理。每个合格小阶段须独立复核、精确提交推送、核对远端 SHA；尚未发生的实施/上传不得预填。密码/认证冻结不变；`v1.14` 同步仍停在只读评审入口 [`quickstart.md`](../ApiRelay/specs/001-key-vault/follow-ups/controlled-ciphertext-sync/quickstart.md)，D01–D17 尚未获批，UI 改版最后另做。完整顺序见 [`release-sequence.md`](../ApiRelay/specs/001-key-vault/follow-ups/controlled-ciphertext-sync/release-sequence.md)。

历史 U11 在 U4 记录末尾续记：组合档旧实现先跑纯生物识别，失败后回到 App 让用户选设备验证，再用新的 `LAContext` 跑设备主人认证，因此会重新触发面容/指纹。现在组合档系统路径与设备验证档一致，只用一个 `deviceOwnerAuthentication` 上下文，系统直接承接生物识别到设备密码的回落；应用密码仍由显式按钮进入。其定向 165 项、全量 454 项和原 iPhone 真机“直接出现设备密码键盘并进入列表、没有再次 Face ID”是对应快照的历史事实，保留在 [U4/U11 记录](../ZL02_研发档案/第一阶段-密钥库/调整与优化/v1.13.9-身份验证四档与主密码调整/18-U4手机循环解锁修复.md)，不冒充最新整体证据。
