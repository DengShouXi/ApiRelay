<h2 id="〇怎么用本页">〇、怎么用本页</h2>

### 接到「更新 10」时（强制；用户不必再贴提示）

用户只说「更新 10 / 整理 10 / 把某段对话补进 10」等，**不必**再口述格式。AI MUST：

1. **打开本页全文**，不要只凭记忆或只扫目录。  
2. **先读完 §一 反复踩坑**（跳转、id、分隔、四套顺序、两套符号——以前最常漏/写错）。  
3. 用 **§二** 确认要动的是哪一块（导航 / 目录 / 某详情 / 五…）。  
4. 编号、符号、换行、表内 id 有疑问 → **只查 §三**（不要另发明一套）。  
5. 打开 **§四 对应小节的清单**，**从上到下逐项勾完再改 `10`**；禁止「只加对话不加子任务」「只改详情不同步五」「漏返回目录 / 大小分隔 / `{stage}-tN`」。  
6. 日常增删状态走 **§五**；改完后用 **Cmd+Shift+V**（或大纲）抽查相关锚点，**不要用** Cursor 标签「Preview」验收 `#锚点`。

`10` 文首引用块、注意事项第二条、仓库 `.cursor/rules/ai-dialog-log-10-11.mdc` 与上表同效；**细则正文只以本页为准**。

### 人眼查阅时的阅读顺序（同强制步骤）

1. §一 踩坑 → 2. §二 骨架（只有地图）→ 3. §三 记号 → 4. §四 清单 → 5. §五 维护。

**防漏、防打架的两条总则：**

| 总则 | 含义 |
|------|------|
| **一条规矩只写死一处** | §二骨架里出现的「三条导航」「返回目录」等，只是点名；**怎么写以 §四清单为准**。不要在两处各写一版细则，免得以后改了一处漏另一处。 |
| **本页与 `10` 冲突** | 以**本页**为准 → 先改本页 → 再改 `10`。 |

<h2 id="一反复踩坑必读加重">一、反复踩坑（必读加重）</h2>

> 下面几条是整理 `10`/`11` 过程中**反复写错**的地方。写错了就会出现：目录能跳、表跳不了；或预览里点了没反应；或两套说法互相打架。

### 1. 页内跳转：用错预览 = 永远跳不动

| 你怎么打开预览 | `#锚点` 能不能滚 |
|----------------|------------------|
| **Cmd+Shift+V**（或命令面板「Markdown: Open Preview」） | **能** ← **只认这个做验收** |
| 左侧大纲点标题 | **能** |
| 编辑器标签上的 Cursor「**Preview**」开关 | **不能**（产品把 `#section` 当文件路径；**改 Markdown 救不了**） |

**错法：** 在 Preview 开关下改锚点写法，以为是文档问题。  
**对法：** 一律用 Cmd+Shift+V 验收。

**跳完找不到落点（Cursor 预览限制）：**

| 事实 | 说明 |
|------|------|
| 外置 CSS / 文内 `<style>` / `:target` | 在本机 Cursor 的 Markdown 预览里**经常整段不生效**→ 无法做到「一点只亮当前那一个」 |
| 内联 `style=` | **能**显示（已验证） |
| **现行做法** | 落点 `<span id>` 内紧跟橙色 **`▌`** 标记（`title="跳转落点"`）。跳转后看视口**靠上**带 `▌` 的那一格 |
| **禁止** | 给落点整格常亮黄底（会误成「多个都亮」；子任务列还会「有的亮有的不亮」） |
| 子任务列 | ✅ 行无 `{stage}-tN` = 无 `▌` = **正常**；🔶/❌ 进五才有 |

改工作区/用户 `markdown.styles` 后须 **Developer: Reload Window**；若 `:target` 某一天突然可用，会叠在 `▌` 上再加黄底（锦上添花，不依赖）。

### 2. 标题锚点：展示名 ≠ id；禁止赌自动 slug

**对法（与现行 `10` 一致）：** 大段 / 汇总 / 详情标题用显式 HTML `id`，目录链这个 id。

```html
<h2 id="一注意事项">一、注意事项</h2>     <!-- 注意：id 里没有顿号「、」 -->
<h3 id="a">A_第一阶段</h3>               <!-- 展示有 A_，id 是小写 a -->
<h3 id="a02">A02_第一大阶段第2次提交_分支 v1.2</h3>
<h3 id="a01--v1131">a01_（A13 下）第1次后续提交_分支 v1.13.1</h3>
<h3 id="release-100">release-1.0.0_商店版本 1.0.0 相关</h3>
```

| 错法 | 为什么错 |
|------|----------|
| 写 `## 一、注意事项`，目录写 `[x](#一注意事项)` | 预览自动 slug 常**保留顿号**再 `encodeURI`，和手写锚点对不上 |
| 标题写 `A_第一阶段`，却设 `id="A"` 或 `id="A_第一阶段"` | 现行 `10` 统一 `id="a"`；目录是 `[A_第一阶段](#a)` |
| 热修详情用 `id="a01"` | 和第一阶段 `A01` 的 `#a01` **撞车**；热修必须用 `a01--v1131` 这种 |

目录上的短文案（如 `A01_v1.1`）只是给人看的；**跳转只认 id**。

### 3. 表内跳转：空标签没用；禁止表下再抄一套标题

| 目的 | 正确落点 | 禁止 |
|------|----------|------|
| 详情子任务「位置」→ 对话名称格 | `<span id="001-d1">…</span>`（可见；名称可再包页内链） | 空 span；`[名称](uuid)` 假装开对话 |
| 详情子任务「涉及对话」→ 某个蕴含短名 | `<span id="001-d1-t1">…</span>`（短名可再包页内链） | 空落点与「位置」写成同一个 |
| 对话表「蕴含」→ 子任务表对应「涉及对话」格 | `<span id="001-d1-t1-s">…</span>`（该链**首次**出现处） | 无 `-s` 却写反向链；多项只包第一次 |
| **五「子任务」** → 详情子任务句 | `<span id="rel100-t2">可见文字</span>` | 表下再写 `#### rel100-t2` 当副本 |
| **五「所属对话」** → 对话名称格 | 名称前的 `<span id="…-dN">` | 链到蕴含短名 `#…-dN-tK` |
| **五「所属小阶段」** → 小阶段详情标题 | 如 `id="release-100"` | 链到对话行或子任务句 |

**详情里四向跳转（页内；Cmd+Shift+V）：**

```text
点「对话名称」→ 该行第一个蕴含短名（#…-dN-t1）
点「蕴含」短名 → 子任务表里首次出现的对应「涉及对话」格（#…-dN-tK-s）
点「涉及对话」→ 滚到蕴含列里那一个短名（#…-dN-tK）
点「位置」    → 滚到该对话名称格（#…-dN）；最终目标是真实 AI 对话（见 [§九 U1](#九未解决问题)，未解）
```

示意：

```html
<span id="001-d1"><span style="color:#c45a00;font-weight:700" title="跳转落点">▌</span><a href="#001-d1-t1">初次上传</a></span> · `uuid`
<span id="001-d1-t1"><span style="color:#c45a00;font-weight:700" title="跳转落点">▌</span><a href="#001-d1-t1-s">推远程</a></span>
<span id="001-d1-t1-s"><span style="color:#c45a00;font-weight:700" title="跳转落点">▌</span><a href="#001-d1-t1">推远程</a></span>
```

写新落点时：`<span id="…">` 后立刻跟上面的 **`▌` 内联 span**（可从邻格复制）。**不要**整格黄底。

**五里三列（与上表一致）：**

```text
点「子任务」    → #…-tN（详情子任务表那一句）
点「所属对话」  → #…-dN（详情对话表「对话名称」格；多项 <br>）
点「所属小阶段」→ 小阶段详情标题 id
```

**错法：** 详情里「涉及对话」「位置」落点撞成一个；五里「所属对话」误链 `#…-dN-tK`；用 `[名称](uuid)` 当开对话。

**未结案：** 「位置」最终应落到 **Cursor 真实对话**——见 [§九 U1](#九未解决问题)。U1 未解前「位置」仍停 `#…-dN`。落点辨认见 [§九 U3](#九未解决问题)（`:target` 不亮，现行用 `▌`）。

### 4. 分隔：大小两级，不要用 `---`

| 场景 | 必须用 | 禁止当成「另一种 ---」 |
|------|--------|------------------------|
| 不同提交 / 不同目录项之间 | 返回目录**之后**一行 `━━━━━━━━…` | `---` / `***` / `___`（预览里同形，分不出大小） |
| 同一次提交内三块之间；五的两张表之间 | 一行 `┄┄┄…` | 用大分隔或再用 `---` |

### 5. 「顺序」有四套，名字都叫顺序——不要串

| 谁的「顺序」列 | 按什么排 |
|----------------|----------|
| 对话表 | **发起该段对话**的时间 |
| 子任务表 | **提出该子任务**的最早时间 |
| 五 · ① 未完成子任务表 | 同子任务表（跨阶段） |
| 五 · ② 推荐完成顺序 | 建议执行：先 🔴→🟡→🟢，同档内再排 |

另：「涉及对话」**列内部**先后 = 该子任务在各对话里被提问的时间（可与对话表总序不同）。

**错法：** 按小阶段编号排五·①（例如强行 A 在前、release 在后）；或把对话表序当成子任务表序。

<h3 id="状态符号">6. 符号有两套，不要进错列</h3>

| 套 | 符号 | 只用在 |
|----|------|--------|
| 完成状态 | ✅ 🔶 ❌ 💬 ⚪ | 目录 / 汇总 / 对话完成状态 / 子任务状态 |
| 重要性 | 🔴 🟡 🟢 | **仅**五·②「推荐完成顺序」的「重要性」列 |

**错法：** 把 🔴 写进对话表「对话完成状态」；或以为 🔴 可以代替 🔶。  
**对法：** 同一行可以同时是 🔴 + 🔶（必须做，但还没做完）。

### 7. Markdown 链接在 Cursor/VS Code 里实际是什么（不要再写成「点开对话」）

依据：

- [VS Code：Markdown](https://code.visualstudio.com/docs/languages/markdown)：无前缀的路径相对**当前文件**解析；`#` 才是页内标题。  
- [CommonMark](https://spec.commonmark.org/0.31.2/#link-destination)：`[税务银行](b2ee007d-…)` 的括号里是 **URL/路径**，不是「会话 id」。没有 `https:` / `cursor:` 时，编辑器就去开一个叫这串 uuid 的**文件** → 「找不到该文件」。  
- [Cursor Deeplinks](https://cursor.com/docs/reference/deeplinks) 只支持 **prompt / command / rule**。本机 `anysphere.cursor-deeplink` 扩展同样没有 `composerId` / 打开历史对话。  
- 论坛 [Create links to past chats](https://forum.cursor.com/t/create-links-to-past-chats/48716) 仍是功能请求。内部命令有 `composer.openComposer`，**没有**公开成 Markdown 可点的 URI。

因此：**`10` 里不可能做到「点对话名称 → 对话栏打开那段聊天」。** 早期写 `[名称](uuid)` 是我们自己的记法，被误当成 Cursor 能力；点得开的是聊天面板里的引用，不是 `.md` 预览。

| 你要点开的 | 靠谱写法 |
|------------|----------|
| **本页**（目录 / 位置 / 五 / 涉及对话） | `[文字](#rel100-d1)` |
| **另一个 md** | `[11](./11-AI对话相关格式要求.md)` |
| **对应哪段 Cursor 对话** | 名称是**页内链**（→ 第一个蕴含），不是普通死文字；uuid 用反引号 `` `…` `` 复制后到历史里搜。**不要**写成 `[名称](uuid)`（会当成文件） |

示意（与现行 `10` 一致；`▌` 见 §一·1 / [§九 U3](#九未解决问题)）：

```html
<span id="rel100-d1"><span style="color:#c45a00;font-weight:700" title="跳转落点">▌</span><a href="#rel100-d1-t1">税务银行</a></span> · `b2ee007d-1159-42b3-8643-80d46099c7d3`
<span id="rel100-d1-t1"><span style="color:#c45a00;font-weight:700" title="跳转落点">▌</span><a href="#rel100-d1-t1-s">协议税务银行</a></span>
```

（蕴含短名不必重复贴 uuid，与名称同一段对话即可。）

### 8. 两个「名称」不要混（`10` 短名 ≠ Cursor 侧栏标题）

| 名称 | 改哪里 | 禁止 |
|------|--------|------|
| **`10` 对话表短名**（税务银行、初次上传、清空按平台…） | 只改本页「对话名称」格、五「所属对话」链接文字 | 换成 Cursor 侧栏原标题（怎么写、Upload to repository…） |
| **Cursor 侧栏里那段聊天的标题** | Cursor 对话栏本身（本机）；**与改 `10` 无关** | 为了「对齐侧栏」去改 `10` 里的短名 |

五「所属对话」、详情「位置」链的**显示文字**跟对话表短名走；「涉及对话」跟**蕴含短名**走。uuid 只写在名称旁反引号里。

<h2 id="三通用记号">三、通用记号</h2>

> 编号、符号、换行、顺序、表种类——**只在本节定义一次**。§四清单会引用这里，不再另起一套。

### A. 编号与展示

| 线 | 汇总标题 | 详情编号 | 详情 id 例 |
|----|----------|----------|------------|
| 第零 | `000_汇总表` | `001`…（三位） | `id="001"` |
| 第一 | `A00_汇总表` | `A01`… ↔ `v1.N` | `id="a01"` |
| 热修 | **也写入** `A00`（或对应大阶段汇总） | `a01_v1.N.M` | `id="a01--v1131"` |
| 商店 | `商店_汇总表` | `release-x.y.z` | `id="release-100"` |

- 序号与说明之间一律 **`_`**，不用 `·`。  
- 大阶段壳：`0_第零阶段` / `A_第一阶段`（禁止光秃 `0`/`A`）。  
- `0`/`A`/`B` 并列；相对 `A00`/`A01`，字母壳略高一级。  
- 汇总表与各子阶段在目录里**同级**；热修在目录里缩进挂在上一小阶段下。  
- 分支分开提交过 → 各占汇总一行 + 详情一块（不因同 tip 合并）。

### B. 符号

定义见 [§一·6](#一反复踩坑必读加重)（完成状态 vs 重要性）。此处不重复表，避免两张表日后改一漏一。

对话 ✅：当且仅当相关子任务都 ✅（或整段仅 💬/⚪）。  
五只收子任务 🔶/❌（不收 💬/⚪）。

### C. 多项换行

- 一格里多个**彼此独立**的项 → 一项一行（表内 `<br>`；阶段说明用嵌套 `-`）。  
- **一句主题不硬拆**（勿见顿号就拆）。  
- 「涉及对话」与「位置」**同行数、同顺序**。  
- 列名用 **「顺序」**。  
- 汇总「内容」：**独立主题才换行**（一句概括里的顿号不硬拆）。

### D. 顺序

定义见 [§一·5](#一反复踩坑必读加重)。此处不另制表。

### E. 表种类与表内 id

| 表 | 写法 |
|----|------|
| 汇总 / 子任务 / 五的两张 / **对话表** | Markdown 管道表 |

| id | 元素 | 谁链过来 / 谁点出去 |
|----|------|----------------------|
| `{stage}-dN` | 对话名称上的非空 `<span id>`；名称文字链到 `#…-dN-t1` | 入：详情「位置」、**五「所属对话」**；出：第一个蕴含 |
| `{stage}-dN-tK` | 蕴含短名上的非空 `<span id>`；短名文字链到 `#…-dN-tK-s` | 入：详情「涉及对话」；出：子任务表对应格 |
| `{stage}-dN-tK-s` | 子任务表「涉及对话」里**首次**出现的对应链外包 span | 入：对话表「蕴含」 |
| `{stage}-tN` | 子任务列非空 `<span>` | **五「子任务」** |

**白话（`{stage}-tN`）：** 五里点「子任务」要滚到详情子任务表那一句；落点是 `<span id="rel100-t2">……</span>`。  
**现行默认：** 只有会进五的行（🔶 / ❌）必须带这个 span；已 ✅ 可不加。  
**`-s` 与 `-tN` 不同：** `-s` 挂在「涉及对话」格（给蕴含反向跳）；`-tN` 挂在子任务句（给五跳）。同一行可以两个都有。
