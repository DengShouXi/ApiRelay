<h3 id="usage-update">接到「更新 10」时（强制；用户不必再贴提示）</h3>

用户只说「更新 10 / 整理 10 / 把某段对话补进 10」等，**不必**再口述格式。AI MUST：

1. **打开本页全文**，不要只凭记忆或只扫目录。
2. **先读完 §1 反复踩坑**（跳转、标题 id ≠ `{stage}`、分隔、四套顺序、两套符号——以前最常漏/写错）。
3. 用 **§2** 确认要动的是哪一块（导航 / 目录 / 某详情 / §5…）。
4. 编号、符号、换行、表内 id 有疑问 → **只查 §3**（不要另发明一套）。
5. 打开 **§4 对应小节的清单**，**从上到下逐项勾完再改 `10`**；禁止「只加对话不加子任务」「只改详情不同步 §5」「漏返回目录 / 大小分隔 / `{stage}-tN`」。
6. 日常增删状态走 **§5**；改完后在 `10` 的文本编辑器中按 **Cmd+Shift+V**，用标题为“对话导航 · 本文件名”的专用预览抽查。编辑器右上角的专用预览按钮是备用入口。

`10` 文首引用块、注意事项第二条、仓库 `.cursor/rules/ai-dialog-log-10-11.mdc` 与上表同效；**细则正文只以本页为准**。

<h3 id="usage-reading">人眼查阅时的阅读顺序（同强制步骤）</h3>

1. §1 踩坑 → 2. §2 骨架（只有地图）→ 3. §3 记号 → 4. §4 清单 → 5. §5 维护。

**防漏、防打架的两条总则：**

| 总则 | 含义 |

| **本页与 `10` 冲突** | 以**本页**为准 → 先改本页 → 再改 `10`。 |

<h2 id="一反复踩坑必读加重">§1 · 反复踩坑（必读加重）</h2>

> 下面几条是整理 `10`/`11` 过程中**反复写错**的地方。写错了就会出现：目录能跳、表跳不了；或预览里点了没反应；或两套说法互相打架。

<h3 id="pitfall-preview">§1.1 · 页内跳转与历史对话：只用专用预览</h3>

| 入口 | 表间跳转 | 打开真实对话 |
|------|----------|--------------|
| `10` 文本编辑器中按 **Cmd+Shift+V** | 能 | 能 |
| 命令面板“对话导航：打开专用 Markdown 预览” | 能 | 能 |
| 编辑器右上角专用预览按钮 | 能 | 能 |
| 普通 Markdown / Markdown Preview Enhanced / Cursor「Preview」 | 可能能 | 不作为支持入口 |

**错法：** 在通用预览里看到对话名称是黑色文字，就继续修改 `cursor://` 白名单。
**对法：** 一律进入标题以“对话导航 ·”开头的专用预览；它由本地扩展直接接收点击，不经过第三方预览的协议过滤。

**跳完如何辨认落点：**

| 事实 | 说明 |
|------|------|
| 实现方式 | `tools/cursor-dialog-navigation/extension.js` 创建专用 Webview；脚本记录最后一次页内跳转并切换唯一高亮类 |
| **目标效果** | 点击 A 后只有目标 A 临时显示黄底；再点击 B，A 恢复、只有 B 显示黄底 |
| **禁止** | 橙红色 `▌`；所有落点常驻黄底；把整行或整格染黄 |
| **当前状态** | **已实现并实测。** 红色 `▌` 与错误的常驻黄底均已删除；点击 A 后仅 A 黄底，再点 B 后 A 恢复、仅 B 黄底 |

`markdown.styles`、Markdown Preview Enhanced 白名单和旧兼容脚本均已从工作区撤掉；不要恢复。四种核心点击行为只以本地扩展的专用预览为准。

<h3 id="pitfall-heading-id">§1.2 · 标题锚点：展示名 ≠ id；禁止赌自动 slug</h3>

**对法（与现行 `10` 一致）：** 大段 / 汇总 / 详情标题用显式 HTML `id`，目录链这个 id。

```html
<h2 id="一注意事项">§1 · 注意事项</h2>     <!-- 注意：id 里没有顿号「、」 -->
<h3 id="a">§2.2 · A_第一阶段</h3>               <!-- 展示有 A_，id 是小写 a -->
<h4 id="a02">§2.2.3 · A02_第一大阶段第2次提交_分支 v1.2</h4>
<h4 id="a01--v1131">§2.2.15 · a01_（A13 下）第1次后续提交_分支 v1.13.1</h4>
<h3 id="release-100">§3.2 · release-1.0.0_商店版本 1.0.0 相关</h3>
```

| 错法 | 为什么错 |
|------|----------|
| 写 `## 一、注意事项`，目录写 `[x](#一注意事项)` | 预览自动 slug 常**保留顿号**再 `encodeURI`，和手写锚点对不上 |
| 标题写 `A_第一阶段`，却设 `id="A"` 或 `id="A_第一阶段"` | 现行 `10` 统一 `id="a"`；目录是 `[A_第一阶段](#a)` |
| 热修详情用 `id="a01"` | 和第一阶段 `A01` 的 `#a01` **撞车**；热修必须用 `a01--v1131` 这种 |

目录上的短文案（如 `A01_v1.1`）只是给人看的；**跳转只认 id**。

<h3 id="pitfall-two-tables">§1.3 · 两张表的页内跳转与真实对话打开</h3>

| 目的 | 正确落点 | 禁止 |
|------|----------|------|
| 对话表「蕴含的子任务」→ 子任务表「子任务」正文 | `[推远程](#001-t1)` → `<span id="001-t1">把工程提交并推到远程仓库</span>` | 跳到「涉及对话」格；另造 `-s` 副本落点 |
| 子任务表「涉及对话」→ 对话表「对话名称」 | `[初次上传](#001-d1)` → `<span id="001-d1">初次上传</span>` | 显示蕴含短名或跳到对话表的「蕴含」短名 |
| **§5「子任务」** → 详情子任务句 | 与第一行共用 `<span id="rel100-t2">可见文字</span>` | 表下再写 `#### rel100-t2` 当副本 |
| **§5「所属对话」** → 对话名称格 | 名称前的 `<span id="…-dN">` | 链到蕴含短名 `#…-dN-tK` |
| **§5「所属小阶段」** → 小阶段详情标题 | 如 `id="release-100"` | 链到对话行或子任务句 |

**详情里只有两条页内跳转（专用预览）：**

```text
点对话表「蕴含的子任务」 → 子任务表「子任务」正文（#…-tN）
点子任务表「涉及对话」   → 对话表「对话名称」（#…-dN）
```

示意：

```html
<span id="001-d1"><a href="cursor://xitong.apirelay-dialog-navigation/open?composerId=uuid">初次上传</a></span>
<a href="#001-t1">推远程</a>
<span id="001-t1">把工程提交并推到远程仓库</span>
<a href="#001-d1">初次上传</a>
```

对话名称与每一条子任务正文都必须有非空 `span id`。红色 `▌` 已废止；动态单目标黄底见 §1.1。

**§5 中三列（与上表一致）：**

```text
点「子任务」    → #…-tN（详情子任务表那一句）
点「所属对话」  → #…-dN（详情对话表「对话名称」格；多项 <br>）
点「所属小阶段」→ 小阶段详情标题 id
```

**错法：** 「蕴含的子任务」跳到「涉及对话」而不是子任务正文；「涉及对话」跳到蕴含短名而不是对话名称；§5 中「所属对话」误链 `#…-dN-tK`；用 `[名称](uuid)` 当开对话。

**打开真实对话：** 文档源码中的「对话名称」和「在对话中的位置」保存同一个 composerId；专用预览把它们渲染成按钮，通过 Webview 消息直接交给本地扩展。预览只显示对话名称，不显示 UUID；UUID 隐藏在链接内部。见 [§9](#九交互实现与兼容说明)。

<h3 id="pitfall-separators">§1.4 · 分隔：大小两级，不要用 `---`</h3>

| 场景 | 必须用 | 禁止当成「另一种 ---」 |
|------|--------|------------------------|
| 不同提交 / 不同目录项之间 | 返回目录**之后**一行 `━━━━━━━━…` | `---` / `***` / `___`（预览里同形，分不出大小） |
| 同一次提交内三块之间；§5 的两张表之间 | 一行 `┄┄┄…` | 用大分隔或再用 `---` |

<h3 id="pitfall-orders">§1.5 · 「顺序」有四套，名字都叫顺序——不要串</h3>

| 谁的「顺序」列 | 按什么排 |
|----------------|----------|
| 对话表 | **发起该段对话**的时间 |
| 子任务表 | **提出该子任务**的最早时间 |
| §5.1 未完成子任务表 | 同子任务表（跨阶段） |
| §5.2 推荐完成顺序 | 建议执行：先 🔴→🟡→🟢，同档内再排 |

另：「涉及对话」**列内部**先后 = 该子任务在各对话里被提问的时间（可与对话表总序不同）。

**错法：** 按小阶段编号排§5.1（例如强行 A 在前、release 在后）；或把对话表序当成子任务表序。

<h3 id="状态符号">§1.6 · 符号有两套，不要进错列</h3>

| 套 | 符号 | 只用在 |
|----|------|--------|
| 完成状态 | ✅ 🔶 ❌ 💬 ⚪ | 目录 / 汇总 / 对话完成状态 / 子任务状态 |
| 重要性 | 🔴 🟡 🟢 | **仅**§5.2「推荐完成顺序」的「重要性」列 |

**错法：** 把 🔴 写进对话表「对话完成状态」；或以为 🔴 可以代替 🔶。
**对法：** 同一行可以同时是 🔴 + 🔶（必须做，但还没做完）。

<h3 id="pitfall-conversation-link">§1.7 · 对话链接在本机 Cursor 中如何工作</h3>

依据：

- [VS Code：Markdown](https://code.visualstudio.com/docs/languages/markdown)：无前缀的路径相对**当前文件**解析；`#` 才是页内标题。
- [CommonMark](https://spec.commonmark.org/0.31.2/#link-destination)：`[税务银行](b2ee007d-…)` 的括号里是 **URL/路径**，不是「会话 id」。没有 `https:` / `cursor:` 时，编辑器就去开一个叫这串 uuid 的**文件** → 「找不到该文件」。
- Cursor 没有公开「按 composerId 打开历史对话」的官方深链；本仓库因此安装了本地适配扩展。它创建自己的专用预览，接收按钮中的 composerId，再调用 Cursor 内部命令 `composer.openComposer`。
- 扩展不读写 Cursor 数据库；uuid 不合法或内部命令不存在时会明确报错。Cursor 大版本更新后需要重跑 §8.3。

因此：裸 uuid 仍然不能直接打开对话；源码使用完整 `cursor://` 地址保存映射，但真正可用的点击入口是本地扩展的专用预览，不是通用 Markdown 预览。

| 你要点开的 | 靠谱写法 |
|------------|----------|
| **本页**（目录 / §5 / 表间定位） | `[文字](#rel100-d1)` |
| **另一个 md** | `[11](./11-AI对话相关格式要求.md)` |
| **对应哪段 Cursor 对话** | 源码中名称与「位置」都保存完整 `cursor://…?composerId=uuid`；专用预览转换为可点击按钮；UUID 只藏在链接内部，不在名称旁显示 |

示意（与现行 `10` 一致）：

```html
<span id="rel100-d1"><a href="cursor://xitong.apirelay-dialog-navigation/open?composerId=b2ee007d-1159-42b3-8643-80d46099c7d3">税务银行</a></span>
<a href="#rel100-t1">协议税务银行</a>
<a href="cursor://xitong.apirelay-dialog-navigation/open?composerId=b2ee007d-1159-42b3-8643-80d46099c7d3" title="打开「税务银行」；位置：前">前</a>
```

（蕴含短名不必重复贴 uuid，与名称同一段对话即可。）

<h3 id="pitfall-names">§1.8 · 两个「名称」不要混（`10` 短名 ≠ Cursor 侧栏标题）</h3>

| 名称 | 改哪里 | 禁止 |
|------|--------|------|
| **`10` 对话表短名**（税务银行、初次上传、清空按平台…） | 只改本页「对话名称」格、§5「所属对话」链接文字 | 换成 Cursor 侧栏原标题（怎么写、Upload to repository…） |
| **Cursor 侧栏里那段聊天的标题** | Cursor 对话栏本身（本机）；**与改 `10` 无关** | 为了「对齐侧栏」去改 `10` 里的短名 |

§5「所属对话」与详情「涉及对话」的显示文字都必须跟对话表名称完全一致，链接目标都是对话名称 `#…-dN`。UUID 同时放进名称与「位置」的真实对话链接，但不得作为可见文字写在名称旁。

<h3 id="pitfall-stage-id">§1.9 · 标题 id ≠ 表内 `{stage}`（热修 / 商店最容易写错）</h3>

标题锚点（目录点进去）和表内 span（§5 / 位置 / 蕴含）**不是同一套字符串**。对照只看 [§3.1](#notation-numbering)，禁止拿标题 `id` 去拼 `-dN`。

| 块 | 标题 `id`（目录用） | 表内 `{stage}`（拼 `-dN` / `-tN`） | 错法 |
|----|---------------------|-------------------------------------|------|
| 热修 `a01_v1.13.1` | `a01--v1131` | `a01v1131` | `id="a01--v1131-d1"` 或热修详情用 `id="a01"`（撞 A01） |
| 商店 `release-1.0.0` | `release-100` | `rel100` | `release-100-d1` / `release-1.0.0-d1` |
| 第零 / 第一小阶段 | `001` / `a01` | 与标题 id **相同** | — |

<h2 id="三通用记号">§3 · 通用记号</h2>

> 编号、符号、换行、顺序、表种类——**只在本节定义一次**。§4 清单会引用这里，不再另起一套。

<h3 id="notation-numbering">§3.1 · 编号与展示</h3>

| 线 | 汇总标题 | 详情编号 | 详情 id 例 |
|----|----------|----------|------------|
| 第零 | `000_汇总表` | `001`…（三位） | `id="001"` |
| 第一 | `A00_汇总表` | `A01`… ↔ `v1.N` | `id="a01"` |
| 热修 | **也写入** `A00`（或对应大阶段汇总） | `a01_v1.N.M` | `id="a01--v1131"` |
| 商店 | `商店_汇总表` | `release-x.y.z` | `id="release-100"` |

- 序号与说明之间一律 **`_`**，不用 `·`。
- 大阶段壳：`0_第零阶段` / `A_第一阶段`（禁止光秃 `0`/`A`）。
- `0`/`A`/`B` 并列；相对 `A00`/`A01`，字母壳略高一级。
- 汇总表与各子阶段在目录里**同级**；热修在目录里缩进挂在上一小阶段下。
- 分支分开提交过 → 各占汇总一行 + 详情一块（不因同 tip 合并）。

**表内 `{stage}`**（拼 `-dN` / `-tK` / `-tN`；一经选定不改；禁止空格）：

| 详情块 | 标题 id | 表内 `{stage}` |
|--------|---------|----------------|
| 第零 `001` | `001` | `001` |

<h3 id="notation-symbols">§3.2 · 符号</h3>

<h3 id="notation-line-breaks">§3.3 · 多项换行</h3>

- 一格里多个**彼此独立**的项 → 一项一行（表内 `<br>`；阶段说明用嵌套 `-`）。
- **一句主题不硬拆**（勿见顿号就拆）。
- 「涉及对话」与「位置」**同行数、同顺序**。
- 「位置」用词只准：`整段` / `前` / `中` / `后` / `前–中` / `中–后`。禁止自造（如「相关」）。
- 列名用 **「顺序」**。
- 汇总「内容」：**独立主题才换行**（一句概括里的顿号不硬拆）。

<h2 id="九交互实现与兼容说明">§9 · 交互实现与兼容说明</h2>

> 四种点击行为已经实现。本节记录实现边界和 Cursor 更新后的复测方法，不属于 `10` §5 的产品欠项。

<h3 id="interaction-behaviors">§9.1 · 四种点击行为</h3>

| 点击处 | 行为 | 状态 |
|--------|------|------|
| 对话表「对话名称」 | 专用预览把 composerId 直接交给扩展，打开 Cursor 真实历史对话 | 已实现 |
| 对话表「蕴含的子任务」 | 跳到 `#…-tN` 子任务正文，并仅将该目标临时标黄 | 已实现、已实测 |
| 子任务表「涉及对话」 | 跳回 `#…-dN` 对话名称，并仅将该目标临时标黄 | 已实现、已实测 |
| 子任务表「在对话中的位置」 | 专用预览打开该行对应的真实历史对话；前/中/后提示阅读位置 | 已实现 |

对话打开后焦点会移动到右侧真实对话。即使同一对话原本已经开着，重复点击也必须重新把它带到前台，不能只显示“成功”而让界面看起来没有反应。

<h3 id="interaction-components">§9.2 · 本地实现组成</h3>

| 文件 / 配置 | 作用 |
|-------------|------|
| `tools/cursor-dialog-navigation/extension.js` | 创建专用 Webview、复用 Cursor 自带 Markdown 渲染器、把对话链接转换为按钮；接收 composerId 后调用 `composer.openComposer`；同时负责表间跳转的唯一黄底 |
| `tools/cursor-dialog-navigation/package.json` | 注册专用预览命令和编辑器标题按钮；扩展本身声明 Cmd+Shift+V |
| Cursor 用户 `keybindings.json` | 把 Cmd+Shift+V 明确绑定到专用预览，避免 Cursor 自带预览、Markdown Preview Enhanced 等同键命令随机抢占 |

对话表只显示可点击的对话名称，UUID 不得作为可见文字跟在名称后面。UUID 必须完整保存在名称和「位置」按钮的 `cursor://…?composerId=` 链接内部。裸 `[名称](uuid)` 仍然禁止，因为它会被当成文件路径；扩展失效时会自动复制隐藏的 UUID，供 History 搜索。

<h3 id="interaction-compatibility">§9.3 · 兼容边界</h3>

- 打开历史对话依赖 Cursor 的非公开内部命令 `composer.openComposer`；没有修改 Cursor 数据库，也没有伪造对话。
- 专用预览不依赖自定义协议白名单、浏览器或本地 HTTP 端口；按钮通过 Webview 消息直接进入扩展。
- Cursor 大版本升级后，如果对话名称或位置点击报“does not expose composer.openComposer”，需要更新本地适配扩展；文档中的 uuid 映射本身仍可继续使用。
- 专用预览内的动态黄底由该 Webview 自己实现，不依赖 Markdown Preview Enhanced。

<h3 id="interaction-retired">§9.4 · 已淘汰方案</h3>

- 裸 uuid、相对文件链、`[名称](uuid)`、直接依赖通用预览放行 `cursor://`：都不能可靠打开真实对话。
- 本地 HTTP 中转：不采用，避免端口冲突和额外浏览器页面。
- `:target`、工作区 `markdown.styles`、文内 `<style>`：在本机预览中不能稳定完成“只亮最后一次目标”。
- 红色 `▌`、给所有目标写静态黄底：不符合用户的一眼定位要求，禁止恢复。
