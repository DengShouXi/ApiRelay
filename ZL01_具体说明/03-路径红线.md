<h2 id="immutable-paths">§1 · 绝对不能动</h2>

### §1.1 · `docs/privacy.md`

**为什么**：这不是普通文档。你填给苹果的隐私政策网址**直接指着这个路径**：

```
https://github.com/DengShouXi/ApiRelay/blob/main/docs/privacy.md
```

**动了会怎样**：网址立刻 404。苹果每次审核都会打开隐私政策网址，
**已上架的 App 在这个网址失效时也可能被下架**。

**连带影响**：`README.md` 用相对路径链着它，也会一起断。

**这是整个仓库唯一一处「文件名本身是对外承诺」的地方。** 其余文件夹怎么改名怎么搬，
最多影响你自己；这一个影响的是已经上架的 App。

> 真要换位置：**先**在 App Store Connect 里把隐私政策网址改成新地址并保存，
> 确认新地址能打开，**再**动文件。顺序反了就是一段真空期。
> 但说实话，没有任何理由值得冒这个险。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### §1.2 · `ApiRelay/specs/`

**为什么**：spec-kit 这个工具把 `specs/` 这个路径**写死在自己的代码里**。

**动了会怎样**：`/speckit.specify`、`/speckit.plan`、`/speckit.implement` 这些命令
全部找不到文件，报错或者在错误的位置新建目录。

**里面同样不能单独搬走的**：

| 路径 | 谁在引用 |
|---|---|
| `specs/playbooks/BRANCHES.md` | `.cursor/rules/versioning-release.mdc` 里写死了这个路径 |
| `specs/playbooks/热修-save.md` | 同上 |
| `specs/playbooks/重要说明/索引.md` | **宪法**里引用了 2 次，另有 4 个文档链着它 |
| `specs/001-key-vault/` | 宪法、路线图、任务清单大量交叉引用 |

想让它们更好找？**加链接，不要搬文件。**
`ZL01_具体说明/00-从这里开始.md` 就是这么做的。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### §1.3 · `ApiRelay/ApiRelay/` 这层同名嵌套

**为什么**：Xcode 工程的标准布局，外层是工程目录，内层是源码目录。

**动了会怎样**：工程打不开，或者源码文件全部丢失引用。

看着别扭，但**不要改**。说的时候写全路径就不会混。

━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━━

### §1.4 · `ApiRelay/.specify/` 与 `ApiRelay/.github/`

**为什么**：spec-kit 的配置、模板、命令定义都在这两处，位置由工具决定。

注意本项目的 spec-kit **只装了 Copilot 集成**（见 `.specify/integration.json`），
所以命令实体在 `.github/agents/` 下——那是 VS Code + Copilot 的位置。
你实际在 **Cursor** 里开发，Cursor 认的是仓库根的 `.cursor/rules/` 和 `.cursor/commands/`。

**两套并存是有意的，不要为了「统一」删掉任何一套。**

<h2 id="movable-paths">§2 · 可以动，但要顺手改引用</h2>

| 路径 | 谁在引用 | 改的时候记得 |
|---|---|---|
| `ZL01_具体说明/` | `README.md`、`重要说明/索引.md` | **只放文件、无子文件夹**；改名要更新链接 |
| `ZL02_研发档案/` | `ZL01_具体说明/` 里多处链着它 | **钉在仓库根**：可改 `ZL` 前缀，不要再搬进别的文件夹（见下） |
| `ZL03_原始素材/` | `ZL01` 链到 README / 截图目录 | 架子（`README.md`）入库；`相关展示截图/` 与 `icon素材/` 已忽略 |
| `ApiRelay/icon/` | 工程图标源 | **权威**。与 `ZL03_原始素材/icon素材/` 职责重叠时，只改这边 |

### §2.1 · 顶层 `ZL` 前缀是什么意思

给人看的中文资料统一用 `ZL` + 两位数字 + `_` + 中文名：

```text
ZL01_具体说明/
ZL02_研发档案/
ZL03_原始素材/
```

- **不要**用 `00-` 这种纯数字开头：数字会排在英文前面，把不能动的 `ApiRelay/`、`docs/` 挤到后面。
- `ZL` 是字母，排在 `ApiRelay`、`docs` 后面；组内按 `01`、`02`、`03` 排。
- Cursor 默认「文件夹一组、文件一组」，所以侧栏最底下永远是 `.gitignore` / `README.md`，
  前缀再怎么起也不可能排到文件后面。这是编辑器规则，不是命名失败。

### §2.2 · `ZL02_研发档案/` 为什么要钉在仓库根

它在 2026-08-22 一天里换过三个位置：先在 `ApiRelay/研发档案/`，又搬到
`具体说明/研发档案/`，最后落在仓库根。三次都没入库，所以没有任何历史能告诉你
「现在到底该在哪」——一份专门讲事故复盘的档案，自己成了最容易丢的东西。

**现在定在仓库根，只允许改 `ZL` 前缀，不要再搬进别的文件夹。** 理由：它有正文，
而 `ZL01_具体说明/` 按约定只放索引文件（00–08）；放进 `ApiRelay/` 又会和代码、规格混在一起。

顺带一条判断标准：**没入库的东西等于随时会丢。** 搬来搬去之前先提交，
至少 `git log` 能告诉你它去过哪。

### §2.3 · `ZL03_原始素材/` 装什么

以前顶层的 `ApiRelay_相关展览/`（英文开头，插在代码旁边）收进本目录后，又改成：

```text
ZL03_原始素材/
├── README.md           ← 入库（空架子说明）
├── 相关展示截图/       ← 不入库（截图、录屏）
└── icon素材/           ← 不入库（png/svg 工作稿）
```

正式送审截图仍在 `ApiRelay/specs/playbooks/.../store-drafts/`（那份才入库）。
**改 App 图标以 `ApiRelay/icon/` 为准**，不要只改 `icon素材/`。

<h2 id="code-red-lines">§3 · 代码里的红线（不是路径，但同样会出事）</h2>

### §3.1 · 测试里不许直接写 `KeychainStore(...)`

必须用 `KeychainStore.makeForTests()`。

**为什么**：测试跑在 `ApiRelay.app` 这个宿主进程里，带的是 App 自己的权限。
钥匙串共享组只有一个，直接构造就会落进 App 自己那一组——
于是测试的清理步骤会**删掉你本机真实的主密码和密钥明文**。

**2026-08-22 就是这么被锁在 App 外面的**，输入正确的主密码一直提示「不正确」，
因为密码根本已经不在了。完整复盘见
[`../ZL02_研发档案/事故复盘/第一次-测试删除主密码/`](../ZL02_研发档案/事故复盘/第一次-测试删除主密码/)。

自检脚本会拦这一条（[`selfcheck.sh`](../ApiRelay/scripts/selfcheck.sh)，H1 已落地）：
测试里直接 `KeychainStore(...)` 会红。确有必要读生产条目时，
在那一行加注释 `// 自检豁免: <理由>`。

### §3.2 · 密钥明文只允许出现在三个地方

**钥匙串**、**单次操作的局部变量**、**剪贴板**。

剪贴板自动清除默认开启、用户可关。MUST NOT 把「可关」改回「必须限时」。MUST NOT 为凑「杀掉 App 后仍清」给 Mac 加系统过期。

MUST NOT 进数据库、MUST NOT 进 iCloud、MUST NOT 进日志——
**包括「只打印前几位」那种**。末四位也不行。

### §3.3 · 跑 `xcodebuild` 必须带 `-derivedDataPath /tmp/ApiRelayAgentDD`

**为什么**：不加就会和 Xcode 抢同一份缓存。后果是 Xcode 下次运行**跳过重编**你刚改的文件，
以及警告的行号**冻结在改动之前**，你改成什么样都不变。这两种问题都极难查。

<h3 id="cloudkit-deploy">§3.4 · 同步实体加了字段，正式包发出前必须再 Deploy Production</h3>

`UserPreferences` 热修加了 `autoLockDurationOptionsJSON`、`clipboardClearDurationOptionsJSON`。
Checkpoint 2b（2026-08）那次 Deploy **没有这两项**。Development 里看得见 ≠ Production 已就绪。

**2026-09-10 Dashboard：** Production 的 `CD_UserPreferences` **已有**这两字段；发展→生产的 Deploy 差异为 0，不必再空跑一次。漏 Deploy 会怎样：TestFlight / 商店包同步丢字段，或变成 CloudKit 错误 10。

此后 **新的**同步字段发出正式包前仍须 additive Deploy Production。2b 已勾 ≠ 再也不 Deploy。详见 `data-model.md` §7.1、FR-063。

<h3 id="cloudkit-no-unique">§3.5 · 同步模型禁止 `@Attribute(.unique)`</h3>

CloudKit 不能给业务 `id` 加唯一约束。两台设备几乎同时插入同一账号，会留下业务 `id` 相同、记录名不同的多行。消重在仓库层做（读去重、写打全、能分出唯一输家才删）。MUST NOT 给同步 `@Model` 加 `@Attribute(.unique)`（和 CloudKit 不兼容）。本热修不做 `replicaSeed`，未 Deploy 不得改 schema 并发包。权威：`data-model.md`「重复行」；实现提示词 [`热修-CloudKit同步卫生.md`](../ApiRelay/specs/playbooks/热修-CloudKit同步卫生.md)。

<h2 id="maintenance">§4 · 这份清单怎么维护</h2>

发现某个路径「动了会出事」，**当场写进本页**，别只记在脑子里。

判断标准很简单：**这个路径有没有被写进代码、配置、或者外部系统（苹果、GitHub）？**

- 只被 md 文档引用 → 可以动，顺手改链接
- 被代码或工具配置引用 → 归到第一节
- 被外部系统引用 → 归到第一节最上面，加粗
