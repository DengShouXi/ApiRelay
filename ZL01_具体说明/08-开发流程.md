<h2 id="before-coding">§1 · 动手前先确认</h2>

| 情况 | 先做什么 |
|---|---|
| 修 bug / 改文案 / 改本夹说明 | 确认人在热修线（见 [`09` §2](./09-上传流程.md#current-branch)），直接改 |
| 需求或阶段范围变了 | 先走 [`07`](./07-计划流程.md)，再动手 |
| 一次对话想顺手改很多处 | 停。一次只改一件事 → [`06`](./06-AI铁律清单.md) |
| 机器侧整改已收、不知下一步 | 先真机抽查；其余按 [`10` §5.2](./10-AI对话相关记录.md#推荐完成顺序) |

现在默认在热修线上干活。保存口令与当前线名只写在 [`09`](./09-上传流程.md)，本页不抄。

<h2 id="specs-or-archive">§3 · 规格还是研发档案</h2>

| 你在干什么 | 写在哪 |
|---|---|
| 改需求 / 阶段范围 / 架构 | **只改 A**：`ApiRelay/specs/`、宪法。地图见 [`04`](./04-设计与规格.md)、顺序见 [`07`](./07-计划流程.md) |
| 事故复盘、验证地基、止血类整改 | **写在 B**：[`ZL02_研发档案/`](../ZL02_研发档案/) |
| 平常推进功能或修 bug | 代码在 `ApiRelay/ApiRelay/`；收工走 [`09`](./09-上传流程.md) |

例：[`第一次-测试删除主密码/00-总览.md`](../ZL02_研发档案/事故复盘/第一次-测试删除主密码/00-总览.md)（战略顺序 H1→H2→…→99；**机器侧已验收通过**）。  
改需求仍回 A，不要把 FR 抄进 ZL02。

<h2 id="done-when">§4 · 做到哪算能收</h2>

1. 改完代码默认跑：

```bash
bash ApiRelay/scripts/selfcheck.sh
```

2. 方案与收尾：[`H1-验证地基.md`](../ZL02_研发档案/事故复盘/第一次-测试删除主密码/H1-验证地基.md)；Cursor 斜杠命令 `/closeout`。
3. 说明夹改完：按 [`12`](./12-通用格式要求.md) 验收链接与目录。对话记录有进展：按 [`11`](./11-AI对话相关格式要求.md) 更新 [`10`](./10-AI对话相关记录.md)。
4. 然后才上传 → [`09`](./09-上传流程.md)。
