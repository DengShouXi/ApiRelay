## 一、两类顶层

| 类型 | 例子 | 能不能改名 |
|---|---|---|
| 英文开头 / 根 README | `ApiRelay/`、`docs/`、`README.md` | **基本不能**（机器、苹果、GitHub 认） |
| `ZL` 开头 | `ZL01`–`ZL03` | 可改前缀数字，但要改完所有链接 |

侧栏里文件夹一组、文件一组；`ZL` 排在英文文件夹附近之后。详见 [`03-路径红线.md`](./03-路径红线.md)。

---

## 二、顶层一览

| 路径 | 装什么 | 常不常进 |
|---|---|---|
| `ApiRelay/` | Xcode 工程、源码、测试、`specs/`、`.specify/`、图标源 | 干活必进（AI 多、你少） |
| `docs/` | 仅 `privacy.md`（隐私政策） | 几乎不进；**路径钉死** |
| `README.md` | GitHub 访客介绍 | 不用当导航 |
| `ZL01_具体说明/` | **本目录**：索引页 00–08，只文件、无子文件夹 | 每次从这进 |
| `ZL02_研发档案/` | 事故复盘与整改方案（有正文） | 出事 / 做 H1… 时进 |
| `ZL03_原始素材/` | 本地素材架：`README` 入库；`相关展示截图/`、`icon素材/` 不入库 | 上架备素材时进 |

`ApiRelay/` 里还有一层同名 `ApiRelay/`：外层工程、内层源码。说的时候写全路径。

## 三、`ApiRelay/` 里和「设计 / 流程」相关的

| 路径 | 装什么 |
|---|---|
| `ApiRelay/specs/` | 需求、路线图、playbooks（分支上传说明书） |
| `ApiRelay/.specify/` | Spec Kit 配置、宪法、模板 |
| `ApiRelay/.github/` | Spec Kit 的 agents / prompts / skills（Copilot 集成） |
| `ApiRelay/icon/` | **工程图标权威** |
| `ApiRelay/ApiRelay/` | 应用源码（见 [`02`](./02-代码地图.md)） |
| `ApiRelay/ApiRelayTests/` | 测试 |

规格与权威正文怎么分工 → [`04-设计与规格.md`](./04-设计与规格.md)。
