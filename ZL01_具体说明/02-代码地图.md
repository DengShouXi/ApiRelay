<h2 id="architecture-layers">§1 · 三层分工（这是本项目最硬的规矩）</h2>

```
UI  ──依赖──▶  Business  ──依赖──▶  Data  ──▶  Apple 框架
```

**箭头只能朝右。** 反着来会编译不过，所以这条规矩从来没被破坏过。

| 层 | 放什么 | 明确不许做什么 | 规模 |
|---|---|---|---|
| `UI/` | SwiftUI 界面 | 不许直接碰钥匙串、网络、数据库 | 14 个文件 · 9757 行 |
| `Business/` | 业务规则、门闩、配额、偏好 | 不许 import SwiftUI | 21 个文件 · 3085 行 |
| `Data/` | 钥匙串、SwiftData、CloudKit | 不许 import SwiftUI | 23 个文件 · 2370 行 |
| `Shared/` | DTO、错误类型；身份清扫指纹/调度（无 SwiftUI、不碰 Keychain） | **不放** Fake；明文清扫日志不许带业务 id | 见 selfcheck |
| `DebugSupport/` | `#if DEBUG` 假零件（`Fakes/`） | 不进正式业务路径；供 Preview + 测试 | 14 个文件 |
| `App/` | 启动、把零件组装起来（含 `makePreview`） | — | 见 selfcheck |

> **界面占了约 58%。** 这不是写多了，是**界面几乎没法自动测试**——179 个测试全打在
> 业务层和数据层，界面只能靠肉眼在模拟器上看。这是当前最主要的短板，
> 整改方案见 [`../ZL02_研发档案/事故复盘/第一次-测试删除主密码/00-总览.md`](../ZL02_研发档案/事故复盘/第一次-测试删除主密码/00-总览.md)。

```bash
cd ApiRelay
xcodebuild test \
  -project ApiRelay.xcodeproj -scheme ApiRelay -configuration Debug \
```

<h2 id="add-files">§4 · 新增文件不用改工程文件</h2>

本工程用的是 Xcode 的**同步文件夹**：往 `ApiRelay/ApiRelay/` 下扔一个 `.swift`，
Xcode 自动纳入编译，**不需要**改 `project.pbxproj`。

反过来说，**放错目录也会被自动编译进去**，所以别乱放。

<h2 id="add-upstream-platform">§5 · 想加一个新的上游平台怎么办</h2>

只做一件事：在 `Data/Network/Adapters/` 下新增一个 `XxxAdapter.swift`。

**不许**改已有的 adapter，**不许**改上层协议。改了就说明设计出问题了，先停下来说清楚。

（`Data/Network/` 目录属于 Stage 2，现在还没建。）
