<h2 id="planning-steps">§2 · 定范围时按这个顺序</h2>

1. 这是哪一阶段的事？  
   打开 [`ROADMAP.md`](../ApiRelay/specs/ROADMAP.md)。不是本阶段的，记下，不要塞进当前实现。
2. 需求有没有变？  
   有：改 [`spec.md`](../ApiRelay/specs/001-key-vault/spec.md)（必要时改宪法，先说明决策）。  
   没有：不要为了「写进计划」去抄 FR。
3. 架构 / 模型要不要动？  
   打开 [`plan.md`](../ApiRelay/specs/001-key-vault/plan.md)、[`data-model.md`](../ApiRelay/specs/001-key-vault/data-model.md)、[`contracts/`](../ApiRelay/specs/001-key-vault/contracts/)。  
   分层与文件在哪 → [`02`](./02-代码地图.md)；这里不重画架构。
4. 对应哪一份 playbook？  
   规划：[`v0-planning/`](../ApiRelay/specs/playbooks/v0-planning/)  
   Stage 1：[`v1-key-vault/`](../ApiRelay/specs/playbooks/v1-key-vault/)  
   Stage 2 / 3：对应目录 `00-README.md`
5. 小阶段怎么收、怎么打分支？  
   打开该目录 `phases/P0N-save.md`。上传步骤见 [`09`](./09-上传流程.md)，不要在本页再写一遍。

中文流程总入口（可选）：[`重要说明/索引.md`](../ApiRelay/specs/playbooks/重要说明/索引.md)。

<h2 id="when-to-plan">§3 · 什么时候才走本页</h2>

Stage 1 已上架商店 **1.0.0**。下一包工程号 **1.0.1** 在热修线 `v1.13.4` 做 TestFlight，**不走本页**（见 [`09` §3](./09-上传流程.md#testflight)）。

| 你要做的事 | 走哪 |
|---|---|
| 修 bug、改文案、改说明夹 | **不走本页** → [`08`](./08-开发流程.md) → [`09`](./09-上传流程.md) |
| 改需求 / 改阶段范围 / 动架构 | 本页 [§2](#planning-steps)，改完再开发、再上传 |
| 开新的 P0N 或进入 Stage 2 | 先读对应 `playbooks/vN-…/00-README.md`，再走 [§2](#planning-steps) |
| 事故复盘、验证地基、止血 | 方案写在 [`ZL02_研发档案/`](../ZL02_研发档案/)；**改需求仍回步骤 2**，不要把 FR 抄进 ZL02 |
