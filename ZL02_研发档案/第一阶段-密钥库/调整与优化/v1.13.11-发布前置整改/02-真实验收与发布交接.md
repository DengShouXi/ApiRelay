# v1.13.11 真实验收与发布交接

- 日期：2026-10-09
- 候选：隔离分支 `codex/release-preflight`，应用版本 `1.0.1 (25)`；执行前以 Git SHA、签名和设备上实际构建号重新确认，不能复用旧 `(24)` 截图代替新构建。
- 判定：本地预检、真实 Sandbox 验收、TestFlight／App Review 是不同关口。`$4.99` 是美国区当前价，不要求其他币种显示字面 `$4.99`。

## 真实环境仍须证明

1. 在 Mac、iPhone、iPad 上以明确的候选构建记录购买／取消／冷启动／手动恢复以及未购买、已购状态；已有历史记录可作为补充，但要核对构建、交易环境和设备身份。Apple 登录与支付密码只由用户在系统界面输入，不交给 AI。
2. 网络恢复后走 Apple **真实 Sandbox 退款**路径，不用 Xcode StoreKit Configuration 的本地退款代替；记录退款申请与最终状态、Apple 已验签交易的 `revocationDate` 或等价撤权证据。若系统页仍“无法连接”，保存时间、设备、网络和错误画面，判为未完成，不推断应用有错或退款成功。
3. 对已退款交易，验证 Mac/iPhone/iPad 的“已解锁”撤销、免费额度、冷启动和跨设备传播。通过须有应用界面／诊断、环境与交易状态相互对应的证据；单独的本机快照、清除测试历史或模拟交易不足以证明真实撤权。
4. 真机覆盖安装前备份并核对容器与钥匙串边界，不为了跑测试再次重置用户数据。此前 iPhone 替换重装损失已被用户接受按现状继续，但不代表已恢复，也不自动授权新一次数据清除。

## 真正分发前的接续顺序

1. 对**将要送测／送审的同一提交和构建**完成独立差异验收，核对 `v1.13.11` 历史 R02 不通过与新预检任务的关系；不得把开发分支上传记作旧九阶段包已正式关账。
2. 已有 iOS、macOS `1.0.1 (25)` 本地 Archive，但两者均为 Apple Development 签名。下一步须取得或由 Xcode／Xcode Cloud 管理 App Store 分发身份，验证正式导出／上传；当前本机只有开发身份，开发归档不能替代分发签名与 App Store 校验。上传后核对 TestFlight 两平台实际构建号、处理状态和安装包来源，再在物理设备重复关键购买／恢复／退款矩阵。
3. 在 App Store Connect 将首个非消耗型 IAP `com.apirelay.iap.unlimited_keys` 与新 App 版本一起提交审核；提交前重新核对商品为“准备提交”、美国价格 `$4.99`、中英元数据、审核截屏、隐私资料和审核备注。旧 `1.0.0` 备注中的默认验证 “None” 不适用于当前包。
4. 真实退款撤权和正式构建人工矩阵由非实施者审查后，再按发布闸门决定公开发布；尚未实测的项目只能明确接受为残余风险或继续阻塞，不能写成通过。

## 已接受但必须如实标注的历史风险

- Catalyst 首次测试宿主异常退出：用户此前接受“未复现但未定位”；后续通过不能说明根因已查清。
- iPhone 临时包替换重装导致的本机容器／偏好损失：用户此前接受按现状继续；没有证据称钥匙串或设置已恢复。
- 真实退款延期：用户同意从 `v1.13.11` 当次分支关账条件移出，但仍是明确未通过的**公开发布前**风险，不能随方法整合自动消失。

方法观察：需把“本地开发签名／Archive 可生成”与“分发身份签名／TestFlight 处理成功”分开记账，避免一个绿色编译结果跨越真实商店与设备闸门。
