# 提示词索引与使用说明

固定工作包：`ZL02_研发档案/第一阶段-密钥库/调整与优化/v1.13.8-多AI协作方法实战验证/`

## 使用方法

1. Codex和Cursor都必须打开仓库根目录；根目录应同时包含`.git/`、`ApiRelay/`、`ZL00_项目总控/`、`ZL01_具体说明/`和`ZL02_研发档案/`。
2. 每次只复制当前阶段提示词代码框内的完整文字，不复制旧聊天或上一阶段全文。
3. 每个阶段完成后停止；不确定进度时使用`通用-只检查当前阶段.md`。
4. 同一工作区同一时间只允许一个写入者。开始下一阶段前确认上一位AI已经停止。
5. 默认把大范围查找、机械核对和批量修改交给额度较多的Grok，把计划、冲突判断和必要独立验收交给Codex；不得因此降低高风险检查。
6. 每份实质性报告自动写简短“方法观察”。用户不需要另行提醒；没有真实问题时一句结束，不生成冗长复盘。
7. 阶段4建立只读检查器后，优先用它恢复阶段；工具非零退出时必须停止，不靠聊天记忆绕过。检查器未实施或失效时，使用`通用-只检查当前阶段.md`的手工后备判断。
8. 每个阶段的最终回复必须用三行结尾：下一步负责人、是否需要用户批准、可直接复制的绝对路径执行句。遇到异常或重复调用时，执行句必须指向本目录的`通用-只检查当前阶段.md`，不得猜下一阶段。

固定三行格式：

```text
下一步负责人：Codex / Grok / 用户
是否需要用户批准：是 / 否（写明批准什么）
下一步：执行 `由当前阶段提示词给出的唯一绝对路径`
```

## 失败轮次

第一次失败使用`整改轮次/R01/`，以后顺序使用`R02`、`R03`。每轮只允许三份产物：`01-Codex整改定稿.md`、`02-Grok整改报告.md`、`03-Codex复验报告.md`。复验再次失败时回到7R创建下一轮，不覆盖旧轮次。

阶段8只接受时间顺序上最新的有效通过报告；不得拿旧通过结论绕过较新的失败报告。

若`RNN/02`已经存在但该轮要求的外部证据仍标为“未验证”，状态是“等待外部证据”，不是7T失败。此时不得创建`RNN/03`或下一轮；用户提供证据或明确授权独立黑盒测试后，再使用`通用-只检查当前阶段.md`恢复。
