## 二、阻塞问题（必须修复）

### B1．允许范围没有被检查器执行

- 输入：在隔离临时仓库中新增一份不在 `allowedModify` / `allowedAdd` 的 `unexpected.txt`。
- 预期：退出 4，停止。
- 实际：退出 0，继续指向阶段5。
- 原因：检查器只读取 `forbiddenPrefixes` 和 `knownUntracked`，没有校验 `allowedModify` 或 `allowedAdd`。
- 连带矛盾：本次 `00C-任务契约.json` 的允许清单未包含 `04`第2.1节已批准的工作包操作台、测试用例和后续提示词；因检查器不执行白名单才没有报错。
- 影响：计划外文件可以混入实施与提交 A，“精确范围”闸门实际失效。

### B2．验收通过后，暂存、`tools/` 与 HEAD 移动可以绕过安全闸门

- 输入：临时仓库已有阶段7通过文件；把受保护的 `tools/x.txt` 加入暂存区。
- 预期：无论处于哪一阶段，暂存区或受保护路径异常都应退出 4。
- 实际：退出 0，`stagingEmpty=false`，仍指向阶段8。
- 原因：最新验收通过后，检查器不再拦截暂存区；同时 `knownUntracked` 在判断 Git 状态类型之前就跳过 `tools/`，使“已暂存/已跟踪的 tools”也被当成允许的未跟踪基线。
- 另一缺口：通过后任意 HEAD 前进即被当成已完成 A/B，直接路由阶段9；契约和检查器没有核对 `origin/main`、`v1`、`origin/v1`、`origin/v1.13.8`、无 `v1.13.9` 及 A/B 产物身份。
- 影响：上传前最重要的范围和分支保护可被绕过。

### B3．阶段报告身份和固定结论可被缺失、引用或伪造

- 缺身份注入：把 `06.md` 改成没有分支、HEAD、方法版本的文本，检查器仍退出 0。`identity_ok` 只检查“有值时是否不同”，没把缺字段当失败。
- 结论引用注入：阶段7报告只写“不要写『验收通过…』”的示例，因包含该字符串，检查器仍路由阶段8。
- 审计结论同样使用“阻塞问题”附近文字的启发式判断，没有唯一可机读结论。
- 预期：身份字段必须齐全；固定结论只能在指定结论位置、且只出现一种。
- 影响：旧报告、示例文本或不完整报告可冒充当前通过证据。

### B4．RNN 整改链不完整仍可放行

- 输入：阶段7失败，`R01` 只有 `01-Codex整改定稿.md` 和 `03-Codex复验报告.md`，故意缺少 `02-Grok整改报告.md`；`03` 写通过句。
- 预期：退出 3，不得跳过执行者整改。
- 实际：退出 0，直接指向阶段8。
- 原因：当前只防“有03无01”，没防“有03无02”，也未对每轮 `01` / `02` 执行完整身份检查。
- 影响：执行与独立验收可在文件链上被跳过，违反本方法的核心独立性。

### B5．“下一步唯一且可执行”未被机检

- 输入：删除临时工作包中检查器将要返回的阶段5提示词。
- 预期：非零停止，改指通用检查或报输入无效。
- 实际：退出 0，返回一条实际不存在的绝对路径。
- 影响：用户仍可在阶段交接时遇到“按提示执行却找不到文件”，这正是本次要消除的返工类型。

### B6．单写入者防护与多 worktree 规则没有形成可执行契约

- 文档如实声明“无法实时锁住外部编辑器”，这一点正确。
- 但检查器只搜索一句固定的“写入状态未停止”文本，契约和阶段提示词却没有规定何时、由谁产生和清除该状态。真实双写时很可能根本没有可检测声明。反过来，测试用例里仅仅引用这句文本也已被当成一个正在运行的写入者；再有一份普通报告引用它，检查器就会误报双写。
- 另一方面，ZL00/04 允许“不同 worktree 经契约管理”，检查器却拒绝任何额外 worktree，无法区分合法的只读/独立工作树与非法双写。
- 影响：实际双写可漏报，合法扩展又会被误拦；“可扩展到多 AI / 多编辑器”还没有稳定落地。

### B7．规定的黑盒唤醒和跨编辑器验证尚未完成

- 静态证据：AGENTS、Cursor 规则和本机 Codex 技能均有正向语义路由、误触发负例、“项目内规则优先”和不扩大上传权边界；位置唯一，未发现 `.codex/skills/` 同名副本。
- 未验证：新 Codex 任务中的正/负例、Cursor 新对话中的正/负例、另一个自有项目规则仓库中的跨项目不污染。本阶段没有获得新建 Codex 任务的授权，也不用当前对话冒充黑盒证据。
- 依据：`05`明确规定“任一关键项未验证，最终结论必须不通过”。
- 影响：目前只能证明文件写了规则，还不能证明两种实际工具会稳定唤醒且不误触发。

### B8．自测套件与执行命令没有覆盖上述高风险失败路径

- 现有 15 项测试覆盖基本恢复、旧 HEAD、禁止路径、暂存、断号和重复契约，但未覆盖 B1—B6 的绕过方式。
- `test_checker_source_has_no_write_git` 只搜索若干带引号的 Git 字符串，可以作为补充，不能代替行为级只读验证。
- 当前 README、`04`和`05`使用 `python3 -m unittest ...`，已实际生成 `__pycache__`，与“测试不往主仓库写产物”矛盾。
- 影响：自测绿色会给出错误安全感；用户每次照文档执行还会产生本地缓存。
