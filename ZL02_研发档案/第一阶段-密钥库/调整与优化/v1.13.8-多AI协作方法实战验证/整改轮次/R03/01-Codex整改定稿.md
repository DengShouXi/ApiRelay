## 2. 获批整改方案

### 2.1 将“唤醒、路由、执行”拆成三个不同权限层级

ZL00/04 为唯一详细规则，AGENTS、Cursor 和本机技能只保留短路由。三层权限必须明确且按以下优先级执行：

1. **仅唤醒**：用户只表达“让 Grok 做、你检查”“两个 AI 相互审计”等协作关系，没有给出具体修改对象、具体任务目标，也没有点名现有阶段或提示词。此时只允许：声明启用方法、绑定当前项目根、读取项目治理入口、运行只读检查器、报告当前阶段及下一提示词。必须在最终回复处停止。
2. **具体任务启动**：用户同时给出了清楚的修改对象或目标，并要求多 AI 分工，但没有调用既有阶段。AI 可以按现行方法定位或建立相应工作包，只执行该任务正常入口允许的规划步骤；不得因为发现旧工作包存在可执行阶段，就把新任务自动并入旧阶段。
3. **现有阶段执行**：只有用户明确说“执行阶段 N / 7R / 7S / 7T”等可唯一识别的阶段，或明确执行现有提示词路径，才构成执行该阶段的授权。仍须受该提示词自身允许范围和批准关口约束。

增加不可被后文弱化的总规则：

> 检查器返回的下一阶段、负责人、`需要用户批准：无`或提示词路径只是状态与路由证据，永远不是执行授权。路由正确不等于用户已经调用下一阶段。

仅唤醒场景不得读取并照做下一阶段提示词，不得创建阶段产物，不得调用另一 AI，不得修改、暂存、提交或上传。最终回复只告诉用户当前状态、下一负责人、是否需要批准和可复制的下一提示词。

### 2.2 给只读检查器增加机器可见的“路由不授权”声明

只读检查器的成功输出同时增加稳定字段与中文提示：

- JSON 字段：`checkerGrantsExecutionAuthority: false`；
- JSON 字段：`authorizationNote`，固定表达“检查器只判断状态和路由，不授予下一阶段执行权限”；
- 文本输出增加独立一行同义提醒。

现有 `requiredUserApproval` 只表示该阶段是否还需额外批准，不得再被解释成“当前对话已经获得执行授权”。README 解释两者区别。单元测试必须断言正常恢复、7R/7S/7T/8 等代表性状态都带有该固定声明；检查器仍然只读。

### 2.3 把项目根隔离落实为工具调用边界

绑定当前项目根后，除读取已安装的全局技能文件和用户明确提供的外部文件外，默认只允许在该根内搜索与读取。未经用户在当前任务中明确授权跨仓库处理：

- 不得执行以项目根父目录、兄弟目录或其他仓库为范围的 `find`、`rg`、文件枚举或 Git 探测；
- 不得调用任务列表、来源任务、父任务、旧聊天或其他窗口来恢复“缺失的具体需求”；
- 任务创建时附带的 `source_thread_id`、来源任务元数据或历史上下文只是传输信息，不是需求来源，也不是跨项目授权；
- 当前输入缺少具体修改对象时，完成仅唤醒范围后停止，向用户索取具体目标或给出下一提示词，不得从来源任务猜测；
- 只有用户明确要求继续某个来源任务，且核对来源任务与当前项目根相同，才能读取其内容；项目根不同则必须先报告并等待重新绑定授权。

外部编辑器入口应采用同一边界：只能以当前打开仓库为根定位规则和工作包，不得用其他窗口补齐当前需求。

- 仅靠措辞无法阻止检查器路由被当成授权：停止，保留证据；不得删除“机器可见不授权声明”来求表面通过。
- 跨项目隔离只能通过关闭全局技能或复制本项目路径才能实现：停止；不得牺牲自动唤醒或把项目专有内容写入全局技能。
- 本机技能无法获得写权限：停止报告，不用仓库副本冒充全局技能。
- 黑盒工具只能通过新建 worktree 运行：停止并改用 `local` 新任务，不得制造临时树。
- 意外出现 worktree、暂存或保护引用变化：立即停止，保留证据，不自动删除或回退。
- 误改冻结文件或 R03/01：停止，不做破坏性恢复；由用户决定。
- R03 复验仍失败：保留 `R03/01—03`，下一轮使用 R04，不覆盖或改写旧证据。

## 8. 方法观察

R02 的同类失败同时出现在 Codex 和 Cursor，说明缺陷不只是某个模型措辞理解不同，而是方法没有把“发现下一阶段”和“获得执行授权”做成两个可机器识别的状态。跨项目失败则说明项目根必须约束实际搜索和会话读取工具，而不能只约束最终选择。R03 因此只补这两道硬边界，并用原句完整回合重测，不扩大为全面重写。

完成本定稿后停止，等待用户确认；不得自动进入 7S。
