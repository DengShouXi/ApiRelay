## 三、固定任务契约

长期模板为`ZL00_项目总控/自动化/task-contract.template.json`，本次实例为`00C-任务契约.json`。两者使用标准 JSON，UTF-8，无注释，便于人和脚本共同读取。

契约必须包含：

- `schemaVersion`、`workPackageId`、`methodVersion`、`sourceKind`、`riskLevel`、`objective`；
- 仓库根、唯一实施 worktree、基线分支/HEAD和保护 refs；
- 规划审计者、检查执行者、用户决策权、各阶段负责人和“单工作区单写入者”约束；

- 风险理由、额度/能力分工、必需闸门、阶段产物图和用户授权点；
- 外部输入清单：来源、日期、适用分支/HEAD、权威等级、新鲜/陈旧结论和未决事项；
- 检查器需要的预期报告名、固定结论句和可重复 RNN 规则。

契约不手写“当前阶段”、“已上传”或“当前写入者正在运行”这类动态事实。下一阶段及当班负责人由产物、Git 状态和`phaseOwners`推导；用户批准记入相应阶段报告，不靠反复改契约。

## 五、只读阶段检查器

### 5.1 唯一实现与命令

实现：`ZL00_项目总控/自动化/check_multi_ai_workflow.py`；自测：`test_check_multi_ai_workflow.py`。

```bash

```

可选`--format json`供其他工具读取；默认输出简短中文。只允许 Python 3 标准库和本机 Git，无 pip、npm或第三方依赖。

### 5.2 输入与输出

输入是仓库根、工作包路径、`00C-任务契约.json`、ZL00/04 方法版本、已有阶段产物/整改轮次及只读 Git 状态。

输出必须包含：契约是否有效、方法版本是否匹配、分支/HEAD/暂存/保护路径、有效和失效产物及原因、是否有多写入者或交接矛盾、唯一下一阶段、负责人、精确提示词路径、需要的用户批准和阻塞原因。

### 5.3 失败安全

- 退出`0`：状态唯一且可安全给出下一入口，不代表已获得用户批准。
- 退出`2`：参数、JSON、schema或必需输入无效。
- 退出`3`：工作链身份、方法版本、分支/HEAD或产物前后关系无效，或存在企图用旧通过产物绕过较新失败的后续产物。一份身份合法的最新失败报告应安全输出下一个7R入口，不自身成为无法整改的死锁。
- 退出`4`：暂存区、受保护路径、多写入声明或 Git 范围异常。

任何非零都是停止，不自动修复。工具不得调用会写入的 Git 命令，不得更改文件、暂存、分支、提交或远程。它与 ZL00 冲突时自身停止，由 ZL00/02 裁决。

## 六、触发、阶段恢复与单写入者

### 6.1 语义触发矩阵

| 类别 | 样例 | 预期 |
| --- | --- | --- |
| 显式协作 | “两个/ 多个 AI”“Codex 和 Grok 一起做”“多编辑器” | 启用方法，定位项目规则与已有工作包 |
| 隐含接力 | “交给另一个 AI 做，你来查”“额度多的模型执行”“复核完再上传” | 同上，但不自动获得写入/上传授权 |

| 主题含 AI 但非协作 | “这个功能用了几个 AI 接口？” | 不触发 |
| 单独上传 | “上传流程是什么”或“上传” | 不因此新建协作包，更不自动上传 |

AGENTS、Cursor 规则和全局技能只保留“意图识别 + 路由 + 权限不扩大”，详细矩阵仅在 ZL00/04 一份。未加载规则的外部 AI 只能使用自包含提示词，不承诺自动唤醒。

### 6.2 阶段恢复

顺序只看：契约→产物身份与固定结论→最新 RNN 轮次→实际 Git 状态与保护 refs。聊天、ZL01摘要或旧通过报告不能覆盖更新的失败产物。任何一项不唯一则输出阻塞，不猜测。

### 6.3 多写入者防护

契约固定唯一实施 worktree和各阶段写入责任人；提示词要求上一位 AI 停止后再开始。检查器根据阶段产物身份、连续性和实际差异报告重叠/冲突的写入声明。两份产物同时自称未停止或不同 worktree 都自称唯一实施点时失败。

本方案不虚构能锁住外部编辑器的实时文件锁；它使用“唯一 worktree + 阶段唯一写者 + 停止交接 + 写后差异检测”防范和发现双写。无法确认上一写入者已停止时，不开始下一写阶段。
