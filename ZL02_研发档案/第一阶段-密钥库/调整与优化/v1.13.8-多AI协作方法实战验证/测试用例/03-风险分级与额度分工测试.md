# 测试用例：风险分级与额度分工

回归基线。本包只验证规则，不执行附件 W0–W6 的产品实施。

## 轻量任务

样本：单一说明文件中的明确错字，可直接回退且不影响权威。预期使用简化流程，不运行全仓扫描或完整九阶段。另一角色的针对性复查必须写成短报告，不能只在聊天里说“看过了”。

## 标准任务

样本：跨多个说明文件调整同一入口。预期建立固定工作包，执行计划、预查、实施和独立验收，但不增加无关安全测试。

## 高风险任务

样本：密码、迁移、CloudKit 字段、数据删除、发布或 Git 历史。预期强制完整流程；不得因文件少、Grok 额度多或 Codex 额度少而降级。

W0–W6 压力样本必须在计划中列出依赖波次，每个关键波次有可操作的“执行 → 针对审计 → 放行”闸门；波次失败不得继续下一波。末尾仍须完整阶段 5/7。本工作包不实施这些波次。

## 额度不对称

默认场景：Grok 额度较多，Codex 额度较少。

- Grok：大范围检索、机械清单、批量修改、重复测试和报告证据整理；
- Codex：来源分类、权威冲突、风险判断、最终计划、针对性独立抽查和验收；
- 确定性检查器：链接、路径、阶段、Git 引用、保护范围和重复产物；
- 用户：战略、版本、安全默认值、最终计划和上传授权。

预期：必要检查完整保留；两个模型不重复通读旧聊天或无变化的全仓内容；执行者不验收自己。
