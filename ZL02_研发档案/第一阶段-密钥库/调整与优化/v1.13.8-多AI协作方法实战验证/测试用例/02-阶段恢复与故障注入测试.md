# 测试用例：阶段恢复与故障注入

回归基线。优先跑 `PYTHONDONTWRITEBYTECODE=1 python3 -B -m unittest ZL00_项目总控/自动化/test_check_multi_ai_workflow.py` 与只读检查器，再人工抽查。

## 正常恢复

不提供旧聊天时，检查器对下列状态各只输出一个下一阶段、一个负责人和一份提示词绝对路径：

- 只有初稿 → 阶段 2
- 已有预查 `03` → 阶段 3
- 已有最终计划 `04`/`05`、无 `06` → 阶段 4（最终计划须用户确认）
- 已实施 `06` → 阶段 5
- 验收失败 → 阶段 7R
- 整改通过 → 等待上传授权的阶段 8
- 已上传且 HEAD 已前进 → 阶段 9

## 故障注入

| 注入 | 预期退出 | 预期行为 |
| --- | --- | --- |
| 报告 HEAD/分支与契约不符 | 3 | 停止；不把该文件当有效前置 |
| 契约方法版本与 ZL00/04 不符 | 3 | 停止 |
| 缺前置却有后续产物 | 3 | 停止，不猜测补齐 |
| 最新失败压过旧通过 | 0 且下一阶段 7R | 不得用旧通过放行阶段 8 |
| 暂存区非空（含验收通过后） | 4 | 任何阶段都停止 |
| 保护路径或业务代码差异 | 4 | 停止；`tools/` 仅当 `??` 未跟踪才放过 |
| 已暂存的 `tools/` | 4 | 不得因 `knownUntracked` 放行 |
| 白名单外未跟踪文件（含工作包内未列名文件） | 4 | 前缀不得单独放行；须精确名单或已登记产物名 |
| 契约列出的扫描文件中任意一份写“写入状态：未停止” | 4 | 停止，不得进入审计 |
| 执行报告缺“写入状态：已停止”却要进阶段5/7/7T | 3 | 停止 |
| 阶段5无通过也无失败句 | 3 | 结论不唯一 |
| 契约 `repository` 等嵌套损坏 | 2 | 简明 schema 错误，无 traceback |
| 只读 worktree 修改已跟踪文件 | 4 | 名单内也必须洁净 |
| 测试用例或非扫描文件仅引用“写入状态：未停止” | 0 | 不得误报双写 |
| 契约外 extra worktree | 4 | 停止 |
| 契约 `allowedReadOnlyWorktrees` 内的只读 worktree | 0 | 允许 |
| 整改轮次断号 | 3 | 停止 |
| 有 RNN `03` 无 `02` | 3 | 停止 |
| 严格产物缺分支/HEAD/方法版本 | 3 | 停止 |
| 报告仅引用通过句、无独立结论行 | 不得路由阶段 8 | 固定结论须独立成行 |
| 下一阶段提示词文件不存在 | 2 | 停止，改指通用提示词 |
| 验收通过后 HEAD 前进但跟踪 refs 未对齐 | 3 | 不得视为已完成 A/B |
| 同一 `workPackageId` 两份契约 | 3 | 停止 |
| 检查器调用 `git add` | 4 | 行为级拒绝，不只靠源码搜词 |

不得自动修复、切换分支、提交或上传。无法确认上一写入者已停止时，不开始下一写阶段。

## 陈旧输入与路牌

用 `00A` 作为候选证据，不以附件为权威：

- 附件仍写在 `v1.13.8` 改身份验证代码，现行路牌是尚未创建的 `v1.13.9` → 必须停止旧计划，不得在本包改 Swift / spec。
- `revealAuthEnabled` / 取用验证出厂开关未由用户拍板 → 不得定稿或实施该默认值。
- 一条指令同时要“完善方法 + 实现密码” → 拆成 ZL02 方法包与 Spec Kit `follow-ups/identity-auth/` 产品包，只记先后依赖，不复制两份产品方案。

## 结果失效

检查和验收只对被检查的 HEAD 及差异有效。新增修改后只重跑受影响项；最终保护边界仍要完整复核。
