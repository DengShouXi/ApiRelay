## 代码事实与风险

1. **权益真相源基本正确。** `Business/System/EntitlementService.swift:62-72,141-160` 每次 `currentTier()` 读取 `Transaction.currentEntitlements`，本地 snapshot 落盘失败不反向推翻结果；`Data/SwiftData/Schema.swift:26-40,100-117` 将 snapshot 放在 local 配置，不走 CloudKit；`Business/System/EntitlementGrantPolicy.swift:10-22` 检查产品 ID、撤销和 `.xcode` 假交易环境。`Business/Vault/KeyVaultService.swift:1221-1230` 在超过 3 把时再询问权益，不用本地 snapshot 单独放行。已有 `Business/System/EntitlementService.swift:82-85` 仅从用户点击恢复入口调用 `AppStore.sync()`，方向符合 [Apple 的恢复购买说明](https://developer.apple.com/documentation/storekit/appstore/sync%28%29)。不应为了修显示问题让 snapshot 成为授权源，也不应在后台自动调用 `sync()`。
2. **设置页把未定论伪装成免费。** `UI/Settings/SettingsView.swift:27,99-106,488-543,1143-1149` 以 `.free` 初始化；`refreshEntitlementTier()` 用 `try? ... ?? .free` 吞掉查询失败，UI 只有“已购/升级”二态。实际买过但首次加载中、查询失败时可能错误显示升级；当前真 `EntitlementService.currentTier()` 的查询本身不抛错、落盘错误被吞，因此“失败”目前主要是协议替身/未来实现可达，不能把它描述成已在真机复现的故障。
3. **付费墙也把查询失败伪装成未购。** `UI/Settings/PaywallView.swift:9-14,24-60,96-122,181-203` 的 `alreadyOwned` 初始为 `false`，权益查询异常也改为 `false`；如果商品已加载，购买按钮即可用。商品拉取失败与权益核对失败是两个独立维度，不应互相掩盖。`PaywallView.swift:206-237` 的购买、恢复结果仅改本页内存状态；取消不显示错误符合预期，但 pending/unverified/product-unavailable 目前经 `Shared/ApiRelayError.swift:108-109` 作为泛化校验错误显示，缺少明确待处理/可重试语义。
4. **刚购成功至额度生效有可验证的时序风险，并非已证实缺陷。** `EntitlementService.swift:94-115` 已对本次 `.verified` 交易校验后直接返回 `.unlimitedKeys`，且特意不等待 `currentEntitlements`；但紧接着用户创建第 4 把时，`KeyVaultService.swift:1221-1230` 调用的 `currentTier()` 又只遍历 `Transaction.currentEntitlements`。若该序列尚未呈现刚购交易，则这一次仍会报免费额度超限。不得用本地无限 snapshot 永久放行来“修好”它；阶段 3 须确定受 verified 交易约束的短暂凭据/重查边界，并以真实 StoreKit 测试证伪或确认。Stage 1 `spec.md:438` 只保证本次 verified 购买不因随后查档失败被报告成购买失败，尚未替代第 4 把即时体验验收。
5. **额度显示有“未知＝无限”混用。** `UI/Vault/VaultHomeViewModel.swift:256-261` 把额度查询错误变成 `nil`，而 `Business/Vault/KeyVaultService.swift:1208-1218` 的 `nil` 原意是无限；`UI/Vault/VaultHomeView.swift:853-855,1627-1634` 因而隐藏免费横幅并允许打开添加表单。真正的第 4 把写入仍受 `KeyVaultService.swift:1221-1230` 闸门约束，故这是显示/操作预判问题，不等于已发现免费越权。当前真权益查询不抛错的限制同第 2 项；仍应以故障注入测试未来错误语义。
6. **跨设备/退款后的显示可能滞后。** `App/AppEnvironment.swift:107-112` 启动监听 `Transaction.updates`，`EntitlementService.swift:46-59` 更新内部快照，但设置页只在首次 `.task` 与付费墙关闭时刷新（`SettingsView.swift:99-106`）；付费墙只有入场 `.task`（`PaywallView.swift:87-89`）。未见两页订阅权益变化的 UI 通知。核心额度在下次业务调用时重读，显示与真实闸门可能短暂不一致。需界定刷新事件、前后台返回及回调乱序，不能把单次画面当作跨设备已验收。
7. **现有测试缺口具体。** `ApiRelayTests/V1/Phase05_Entitlement/EntitlementServiceTests.swift:25-72` 覆盖脏 snapshot、产品/环境/退款策略，但没有购买成功后立刻创建第 4 把、pending、取消、恢复、退款后的 UI 或故障显示测试；`ApiRelayTests/V1/Phase03_Vault/KeyVaultServiceTests.swift:122-167,201-228` 覆盖免费 3/4、无限 4、脏 snapshot，不覆盖购买与配额交界。`DebugSupport/UITesting/UITestFixture.swift:26` 把所有 UI 场景权益固定为无限，`ApiRelayUITests/` 当前没有购买界面用例。`Configuration/ApiRelay.storekit:6-25` 有非消耗型产品和匹配 ID；`ApiRelay.xcodeproj/xcshareddata/xcschemes/ApiRelay.xcscheme:54-80,124-126` 只有 LaunchAction 引用该 StoreKit 配置，不能由此宣称 TestAction 已接入自动 StoreKit 交易测试。[Apple 的 SKTestSession 说明](https://developer.apple.com/documentation/storekittest/sktestsession) 允许测试购买、退款等，但共享一个测试环境，改变其状态的用例须串行。
8. **原 `13.9` 草稿仅可吸收需求。** 只读 `git diff -- SettingsView.swift Localizable.xcstrings project.pbxproj` 显示，旧草稿只给设置页增加 optional 档位、lookupFailed 与“核对中/无法核对”两条中英字符串；未处理付费墙、额度未知、购买到配额时序或 UI 自动测试。其 `project.pbxproj` 同时含构建号 11、Xcode 工具设置等混杂差异。`13.11` 的 `SettingsView` 已经历结构调整，不能整块复制旧 hunk；本包只能在新基线重新实现对应需求，绝不带入旧工程差异。
