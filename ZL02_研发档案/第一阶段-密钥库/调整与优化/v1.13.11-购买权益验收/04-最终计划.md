# v1.13.11 购买权益最终计划

阶段：3；日期：2026-09-24；分支：`v1.13.11`；起始 HEAD：`8e6c22109b9f5851dacb31b96e8915d855b0e0f3`。输入：本包 00C、00D、01–03，现行 Stage 1 FR-026–029/FR-062，Apple StoreKit 文档及当前代码。授权：用户明确要求单 AI 在本独立分支连续完成计划，不再逐阶段提示；仅覆盖购买权益，不授权 `v1`、`main`、tag、Archive、TestFlight、App 审核或 `v1.14` 同步。

## 决定与不变量

1. 保留 StoreKit 2 的已验证交易为唯一付费授权事实；本机 `EntitlementSnapshot` 只供观测，不得在缺少有效交易时放行。免费上限仍为 3；退款后超额旧密钥只读保留。产品 ID、家庭共享和商店配置不变。
2. UI 将权益核对明确分成核对中、免费、已购、暂不可核对。未确认免费时不展示可执行购买动作；查询失败给重试/恢复入口，不声称用户未购。商品加载与权益核对分离。请求采用代次，旧响应不得覆盖较新结果；前台返回必须复核。
3. 额度的 `nil` 仅表示无限，不再兼作错误；显示层有独立的未知/不可核对状态，业务写入仍由 KeyVaultService 最终检查。
4. `pending`、取消、失败和恢复结果分别表达；未验签、退款或错误不得授予权益。购买成功后第 4 把的时序风险先用 StoreKit 本地交易测试验证；只有证实后才允许受已验证交易约束的最小衔接，不引入永久缓存授权。
5. 真机 Sandbox/跨设备/退款是独立于 Xcode 本地 StoreKit 的验收项。无法取得设备或测试账号时如实保留发布阻塞，不用模拟器代替。

## 执行波次

- A · 先增加可控 UI fixture 与状态/业务回归测试，再修设置页、付费墙和额度未知态；中英本地化同时核对。每波运行定向测试和 `git diff --check`。
- B · 接入 `SKTestSession` 串行购买/恢复/退款测试；验证 verified 购买后立即新增第 4 把。仅实测证实时修 EntitlementService 衔接；不得借用本地 snapshot 放行。
- C · iPhone/iPad 模拟器、原生 Mac 与 Catalyst 编译和相关 UI 测试；可用真机再跑真实 Sandbox 路径。保留原冻结认证回归，至少跑受影响套件和完整单元测试。
- D · 单 AI 按用户最新明确指令独立做两遍检查：第一遍测试/静态范围核对，第二遍停写后按最终 diff、保护 refs、真实测试产物重新核对。此例外**不冒充 MAIC-1.3.1 的另一角色独立验收**。只有自动闸门全通过且范围正确，才按用户本次授权精确提交推送 `v1.13.11` 开发分支并读取远端 SHA；即使推送成功，也不据此推进 `v1` 或宣称发布/真机验收完成。

## 停止与回退

- 任何修改牵涉密码/认证、CloudKit 同步、产品 ID、永久购买凭据、商店后台、用户真实数据迁移或购买语义新决定时停止该部分，先报告用户。
- 真机不可用、Sandbox 产品/账号不可用或外网失败不伪造结果；可继续纯本地测试及隔离分支工作，但发布验收保持未完成。
- 不使用 reset/force；各波以精确 diff 与提交隔离，可由独立分支提交回退。原 `v1.13.9` 脏树及 `v1.13.10` 只读快照不得修改。

方法观察：用户明确拒绝逐阶段双 AI 接力，本计划仅在 `v1.13.11` 范围内采用单执行者连续工作；这不改变仓库通用治理文件，也不把自检写成独立验收。

用户发现曾用 App Store Connect 普通开发者账号做购买测试；当前团队的 Sandbox 测试账户列表为空，现有“已解锁”尚未证明是真实 Sandbox。按以下顺序补强，不改变产品 ID、价格、密码、云同步或用户数据：

1. 保留 StoreKit 已验签交易为唯一授权；本地权益快照只作观测。核对 Debug fixture 只在指定 UI 测试环境生效，给快照注释纠偏。
2. 将默认 Xcode Run 与本地 `.storekit` 配置分离；本地 StoreKit 自动测试仍保留在 TestAction。建立静态检查，避免后续 Run 无意使用假商店。
3. 将“新活跃密钥超过免费 3 把需已购”的规则复用于普通新增、回收站恢复和备份导入。备份导入在共享独占写栅栏内逐条复核；免费态超额则走现有 WAL 回滚，备份文件与原有数据保留。补免费拒绝、已购允许、回滚零残留和旧超额数据保留回归。
4. 重跑受影响测试、完整单测、iPhone/iPad UI、本地 StoreKit、Mac/Catalyst 编译；每项记录对应快照，不拿这些替代真实 Sandbox。再用一个有效 Sandbox 测试账户核对购买、取消、恢复、退款及跨设备；账号凭据和付款面板由用户本人操作。尚无真实证据时保持 `v1.13.11` 未关账。

本补强仅扩展本包精确文件白名单，新增范围见 `00C`；不得触碰原 `v1.13.9` 工作树或推进 `v1`、`main`、TestFlight、商店审核。后续提交与推送仍按治理总纲另取明确授权。

## 2026-09-28 成熟实现收敛（用户已批准实施）

用户指令：“参考的GitHub成熟项目与制定的方案，有序实现代码”。本轮只实施购买权益，不授予提交、推送、后台操作或真实付款的新授权。

- 参考 RevenueCat/purchases-ios 的 StoreKit2TransactionListener 与对应测试：交易入口统一、取消/pending/未验签分开、可注入外部交易流；不引入 RevenueCat 托管后台。审阅源码 SHA `a2465d4abaea95560d48bfb14ebcd4dbf8304500`，仅作参考，不作为依赖。
- 参考 apple/sample-backyard-birds 的 BirdFoodShop，验证并采用 Apple ProductView 发起购买；自定义购买按钮仅在明确的 DEBUG UI fixture 中使用，不与原生购买重复调用。参考 SHA `1843d5655bf884b501e2889ad9862ec58978fdbe`。
- 不接入 SwiftyStoreKit；Dropbox/StoreKitTestHelpers 仅参考有界等待，不采用订阅专用判断或超时跳过验收。
- EntitlementService 仍为业务授权入口，新增可注入 StoreKit 适配器；设置、付费墙、列表共享同一展示状态。任何本地快照不得变成授权来源。
- 已验签购买结果与交易更新进入同一入口。仅允许本次有效已验签交易在进程内提供最多 5 秒的缓存到达衔接；撤权/显式恢复立即终止衔接，未知验签不得被衔接掩盖，期限过后回到 StoreKit 查询，不持久化该衔接。

- 所有结果记录到本包；自动测试不替代真实 Sandbox。iOS 26.5 `notEntitled` 单独保留失败证据，不关闭验签或跳过用例。本轮继续单 AI，停写自检不冒充另一角色独立验收。
