# v1.13.8 项目治理体系整理：执行计划初稿

> 状态：等待 Grok 阶段 2 实施前检查；不是最终执行计划。

## 一、整理结果

形成“一个方法论中心、两条工作来源、一个中文状态中心、一套可追溯变更闭环”：

- 用户是最终决策者。
- `ZL00_项目总控/` 是书面的最高治理方法论，只规定权威边界、冲突裁决、变更闭环和发布闸门，不收纳具体任务工作包。
- `ApiRelay/specs/` 保存通过 Spec Kit 框架开展的完整过程，包括规格、计划、任务、检查、实施依据、审计和结果。
- `ZL02_研发档案/` 保存非 Spec Kit 工作，即实际使用后产生的问题、事故、调整、修改意见，以及相应的计划、检查、实施、审计和结果。
- `ZL01_具体说明/` 用中文说明当前状态、正在做什么、下一步和已经批准的决定，并保存AI对话索引与项目演进记录，供非技术人员阅读；不承载完整技术工作包。
- AI 对话是证据和演进记录，不是单独的权威来源。

工作来源判定规则：通过 Spec Kit 发起的建设进入 `ApiRelay/specs/`；实际使用后产生的非 Spec Kit 调整进入 ZL02。若 ZL02 调整最终改变正式规格，过程记录不搬家，只把获批结论回写 `ApiRelay/specs/`。

## 二、实施阶段

- `ZL00_项目总控/03-关账与发布闸门.md`

治理中心必须回答：谁能作最终决定、每类信息由谁负责、冲突时先听谁、什么情况下可以改变 Spec Kit、改变后怎样回写、未完成回写时为什么不能正式实施或发布。治理中心不得保存本次或其他具体任务的执行计划、检查报告、实施记录和审计结果。

计划建立根目录 AI 入口和 Cursor 路由文件，但它们只能指向 ZL00，不得复制另一套规则：

- 根目录 `AGENTS.md`
- `.cursor/rules/project-governance.mdc`

### B. 建立统一冲突裁决机制

统一流程：

1. 发现 Spec Kit、ZL01、ZL02、AI 对话、开发流程或上传流程存在冲突；
2. 先停止受冲突影响的正式实施或上传；
3. 根据工作来源记录过程：Spec Kit 工作写入 `ApiRelay/specs/`，非 Spec Kit 调整写入 ZL02；
4. 用户批准保留现状或改变方案；
5. 获批变化回写到真正负责该内容的正式文件；
6. ZL01用中文更新当前状态；
7. 完成一致性检查后恢复实施或发布。

不得采用“最新文件优先”“写得最详细的文件优先”或“某个 AI 的回答优先”。紧急事故允许先止血，但必须补做裁决和回写。
