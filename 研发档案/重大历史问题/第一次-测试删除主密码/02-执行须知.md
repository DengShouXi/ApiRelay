# 02 · 执行须知（每一步开工前必读）

> 本文件是给**执行模型**看的通用硬约束。`H1` ~ `H4` 每份提示词开头都会引用本文件。
> 读完本文件再打开对应的 `Hx` 文件执行。

---

## 一、你的身份与范围

你在执行一份**已经定好的**整改步骤。方案是提前想好的，**你不需要自己设计，也不许自己改方案**。

你只做当前 `Hx` 文件里明确写出来的事。**写了才做，没写不做。**

---

## 二、五条铁律

### 铁律 1 · 只改本步骤列出的文件

`Hx` 文件里有「改哪些文件」和「不许碰的文件」两份清单。

- 清单外的文件**一律不许改**，哪怕你觉得它有 bug、有笔误、命名不好、可以顺手优化。
- 发现顺路可以改的东西，**记下来写进报告，不要动手**。

### 铁律 2 · 验证不过就停手，不许自己修

任何一步的验证命令没通过：

1. **立刻停止**，不要继续下一步。
2. 把**完整的错误原文**贴出来（不要摘要、不要只贴最后一行）。
3. 说明你停在哪一步。
4. **不许**自行改方案、不许跳过、不许把报错的代码注释掉、不许降低验证标准。

同一步**连续两次**没通过 → 停手，报告「需要升级到贵模型」。

### 铁律 3 · 不许提交任何东西

**MUST NOT** 执行 `git commit`、`git push`、`git checkout -b`、`git merge`、`git reset`、
`git stash`、`git tag`、`git rm`。

提交由项目负责人决定。你只改文件，改完报告。
（`git status` / `git diff` 这类**只读**命令可以用。）

### 铁律 4 · 提示词与实际文件对不上就停手

`Hx` 里会给出行号和原文片段。如果你打开文件发现**内容对不上**，说明文件已经被改过、
提示词过期了。

**停手报告，不要凭猜测找一个「差不多的位置」下手。**

### 铁律 5 · 碰到密钥与用户数据立刻停

看到下列任何一项，而**当前步骤没有明确写要做这件事**：

- 删除 / 重置主密码、备份口令、管理凭证
- 调用 `eraseAllUserData()`、`MasterPasswordService.reset()`
- 对 Keychain 做枚举后批量删除
- 卸载 App、删除 App Group 容器

**立刻停手报告。** 这次事故就是这类操作在无人察觉的情况下删掉了用户本机真实的主密码。

## 三、构建与测试命令（必须原样使用）

> 下面的参数**不是可选的**。少一个都会出问题，而且出的问题很难查。
> **不要**自己简化命令、不要去掉任何参数。

工作目录一律是 `<仓库根>/ApiRelay/`（即 `ApiRelay.xcodeproj` 所在目录）。

### A. 只想知道「编不编得过」——用 Mac Catalyst

```bash
xcodebuild build \
  -project ApiRelay.xcodeproj \
  -scheme ApiRelay \
  -configuration Debug \
  -destination 'platform=macOS,variant=Mac Catalyst' \
  -derivedDataPath /tmp/ApiRelayAgentDD
```

### B. 跑测试——用 iOS 模拟器，必须带本地签名

```bash
xcodebuild test \
  -project ApiRelay.xcodeproj \
  -scheme ApiRelay \
  -configuration Debug \
  -destination 'platform=iOS Simulator,name=iPhone 17 Pro' \
  -derivedDataPath /tmp/ApiRelayAgentDD \
  CODE_SIGN_IDENTITY="-" \
  CODE_SIGNING_ALLOWED=YES \
  CODE_SIGNING_REQUIRED=YES
```

### 为什么这些参数不能省

**`-derivedDataPath /tmp/ApiRelayAgentDD`**：不加就会和 Xcode 抢同一份缓存。后果有两个，
都很难查——Xcode 下次 Run 会认为产物是新的而**跳过重编**你刚改的文件；
以及增量编译会**重放上一次的诊断**，于是警告的行号、列号、代码片段全部冻结在改动之前，
你改成什么样都不会变。

**签名三件套**：不带签名写出的包会让下一次 Run 被系统拒绝
（`FBSOpenApplicationServiceErrorDomain` / POSIX 163）。只做「编过没」时优先用 A（Mac Catalyst），
不要无签名去编 iPhone 模拟器。

### 如果 destination 报错

模拟器名称可能因机器而异。用下面的命令看当前可用的：

```bash
xcrun simctl list devices available | grep iPhone
```

换成列表里存在的名字。**如果换了名字还是报错，停手报告，不要继续。**

## 四、不许碰的文件（全局，所有步骤通用）

除非当前 `Hx` 文件**明确点名**要改，否则下列一律不许改：

| 路径 | 为什么 |
|---|---|
| `ApiRelay/specs/**` | 规格与计划是决策记录，改它要先说明哪条决策变了 |
| `ApiRelay/.specify/memory/constitution.md` | 宪法。改它必须同步更新版本号与影响报告 |

| 付费墙相关代码与文案 | 明确要求过不要顺手改 |
| `ApiRelay_相关展览/` | 截图与录屏，与代码无关 |

## 五、这些控制台输出是噪音，不要为它们改代码

模拟器上每次运行都会打印下面这些。**它们不是 bug，不是回归，MUST NOT 为消除它们
去改业务代码、设置页、布局约束或宪法。**

| 输出 | 是什么 |
|---|---|
| `hapticpatternlibrary.plist` / `CHHapticPattern` / `_UIKBFeedbackGenerator` | 模拟器没有振动马达 |
| `_UIRemoteKeyboardPlaceholderView` / `_UIKBCompatInputView` 约束冲突 | 系统键盘内部约束，UIKit 老问题 |
| `TUIKeyboardCandidateMultiplexer` | 系统键盘候选词 |
| `Failed to send CA Event` / `FirstFramePresentationMetric` | 系统启动遥测 |
| `Could not validate account info cache` | 系统账号缓存 |
| `No iCloud account` / `CloudKitSchemaBootstrap skipped` | 模拟器未登录 iCloud，设计如此 |

只有 `[ApiRelay] …` 开头的才是本项目自己的日志。

### 一个特殊情况：警告的行号一动不动

如果某个警告钉在 `}` 或空行上，或者多次构建后行号列号**一个字节都不变**而源码明明改过，
或者警告文本引用的代码在当前文件里**已经搜不到了**——那是增量编译缓存重放，不是真警告。

处理办法：`rm -rf /tmp/ApiRelayAgentDD` 后重新构建。**MUST NOT 为此再改业务代码。**

## 六、完成后必须报告什么

每一步做完，按下面的格式报告。**缺项视为没做完。**

```
## 步骤：<Hx 文件名>

### 改了哪些文件
- 路径（新增 / 修改）：一句话说明改了什么

### 没改哪些文件
- 明确确认「不许碰」清单里的文件一个都没动

### 验证结果
- 步骤 1 验证命令：<原样贴命令> → 通过 / 未通过
- 步骤 2 验证命令：<原样贴命令> → 通过 / 未通过
- （逐条列全，不要合并成一句「都通过了」）

### 顺路发现但没有动手的问题
- （没有就写「无」）

### 未完成 / 有疑问的地方
- （没有就写「无」）
```
