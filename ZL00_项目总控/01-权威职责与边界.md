# 01 · 权威职责与边界

先判断问题属于哪一类，再打开对应权威。不要把摘要页、对话记录或某次工作包当成另一类资料的替身。

## 四类项目资料

| 位置 | 管什么 | 不管什么 |
| --- | --- | --- |
| `ZL00_项目总控/` | 治理方法、职责边界、冲突裁决、关账与发布闸门 | 某次任务的计划、检查、实施、审计；当前版本正在做什么 |
| `ApiRelay/specs/` | 通过 Spec Kit 开展的规格、计划、任务、检查、实施依据、审计和结果 | 实际使用后产生的非 Spec Kit 事故/优化全过程；中文通俗导航 |
| `ZL02_研发档案/` | 实际使用后产生的调整、优化、事故及其计划、检查、实施、审计和结果 | 正式产品规格正文；长期治理方法论 |
| `ZL01_具体说明/` | 中文导航、通俗说明、当前状态、AI 对话索引和上传流水账 | 完整技术工作包；第二套规格或第二套最高治理 |

工作来源判定：通过 Spec Kit 发起的建设进入 `ApiRelay/specs/`；实际使用后产生的非 Spec Kit 调整进入 ZL02。若 ZL02 调整最终改变正式规格，过程记录留在原工作包，只把获批结论回写对应 spec / 路线图 / 宪法。

## 其他入口的边界

| 位置 | 角色 |
| --- | --- |
| 用户当前任务中的明确决定 | 最高优先级；涉及战略、版本归属、安全、发布或不可逆操作时必须由用户批准 |
| `ApiRelay/.specify/memory/constitution.md`、`ApiRelay/specs/ROADMAP.md`、现行 `spec.md` | 产品内容权威：原则、阶段范围、需求正文 |
| `.cursor/rules/` | AI 操作纪律；其中 `project-governance.mdc` 只路由到本目录 |
| `AGENTS.md`、根 `README.md` | 入口，不复制规则正文 |
| `ZL01_具体说明/14-项目当前状态.md` | 唯一中文“现在是什么、正在做什么、下一步” |
| `ZL01_具体说明/10-AI对话相关记录.md` | 对话与子任务索引；不能单独成为项目决定 |
| playbooks / `ZL01` 的 07、08、09 | 计划、开发、上传的操作说明；服从本目录的闸门 |

## 禁止

- 把同一次完整技术过程同时复制到 ZL00、Spec Kit 和 ZL02，形成多份权威。
- 用 ZL01 的摘要反向覆盖 spec、宪法或 ZL02 工作包结论。
- 用“文件更新时间更晚”代替裁决。
- 把尚未批准的建议写进正式实施或上传。
